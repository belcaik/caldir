# W1-C2: Exercise task update and delete under TaskPushes::Allowed

**Provides:** — · **Needs:** P1-03 (landed) · **Origin:** Wave 1 review finding, LOW

## Responsibility
`P1-03`'s acceptance criterion 4 names task **create, update and delete** each reaching the
outgoing set when the provider advertises `tasks.write`. Only `Create` is exercised under
`TaskPushes::Allowed`; `Update` and `Delete` are exercised only under `Withheld`.

## Why it is LOW and not a defect
The `TaskPushes::Allowed` arm is a bare `=> 0` with no per-item-kind and no per-change-kind
branching, so `Create` passing is a sound proxy. Nothing is known to be broken. The gap is that
the criterion as written is not fully exercised, and a future edit that *introduces* branching
there would not be caught.

## Acceptance criteria
1. `EventChange::Update` for a task reaches the outgoing set under `TaskPushes::Allowed`.
2. `EventChange::Delete` for a task reaches the outgoing set under `TaskPushes::Allowed`.
3. The existing withheld-side assertions stay green, unmodified.
4. `discard_outgoing()`'s zeroing test is untouched.

## Non-goals
- No production-code change. If reaching green requires editing `calendar_diff.rs`, stop and
  escalate: that would mean the `Allowed` arm has branching the review did not find, which is a
  different and more serious finding than this ticket.
- No task dispatch (`P2-01`), no CLI message text (`P2-05`), no `suppressed_task_deletes` (`P2-06`).
