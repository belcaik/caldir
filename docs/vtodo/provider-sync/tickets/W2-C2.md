# W2-C2: Test the wire-code to error-class mapping

**Needs:** P2-04 (landed, `151c720`) · **Origin:** Wave 2 review finding, MEDIUM

## Responsibility
`provider::error::classify` maps each `rpc::ErrorCode` to its `ProviderError` variant. It has
**one production caller** (`Provider::call`, `caldir-core/src/provider.rs`) and **zero test
callers**. Four of the six §16 classes — `MissingAuthScope`, `RemoteNotFound`, `Conflict`,
`SemanticLimitation` — have no test exercising the mapping at all.

**Proven by mutation:** the reviewer scrambled those four match arms so each returned a different
class, and **650 of 650 tests still passed.**

## Why the existing tests miss it
- `every_error_class_round_trips_over_the_wire` serializes and deserializes `ErrorCode` through
  `Response`. It never calls `classify`.
- `a_missing_scope_failure_is_distinguishable_without_string_matching` constructs
  `ProviderError::MissingAuthScope` directly through a `From` conversion. It never calls
  `classify`.

Both test real things. Neither tests the mapping.

## Acceptance criteria
1. Each of the six §16 wire codes, plus `UnsupportedMethod`, plus `Unrecognized`, plus absent
   (`None`), maps to its specific expected `ProviderError` variant — asserted per code. Table-driven
   is fine; **one assertion per row**, not a single aggregate.
2. **The mutation that motivated this ticket now fails.** Scramble the four arms locally, confirm
   the new test fails, revert, confirm green. Report the failure output.
3. Prefer driving through `Provider::call` with a mocked wire reply where practical, so the test
   covers the real path from envelope to typed error rather than the helper in isolation. Falling
   back to calling `classify` directly is acceptable if the mock plumbing is disproportionate —
   say which you did.
4. `Network` maps to `ProviderError::Transport(ProviderTransportError::Network(..))`, not to a
   second network variant. Pin that specifically; it is the one asymmetric row.

## Non-goals
- No change to `classify`'s behaviour. If a mapping turns out to be **wrong**, stop and escalate —
  that is a defect report, not a fix to make quietly under a test-only ticket.
- No new error class, no public-surface change (`W2-C1` owns that).
