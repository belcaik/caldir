# W1-C1: Realign the provider-author guide with the shipped Handler trait

**Provides:** — · **Needs:** P1-04, P1-06 (both landed) · **Origin:** Wave 1 review finding, MEDIUM

## Responsibility
`P1-06` (`339842d`) was authored against the pre-`P1-04` `Handler`. `P1-04` (`8fbb70c`) then
renamed the write methods and retyped their payloads, and the two documents were never updated.
They now instruct an out-of-tree provider author to write code that cannot compile.

## The drift, measured
Shipped at HEAD (`caldir-core/src/provider/handler.rs`, grep the symbols):

    async fn create_item(&self, _cmd: CreateItem)  -> Result<CalendarItem>
    async fn update_item(&self, _cmd: UpdateItem)  -> Result<CalendarItem>
    async fn delete_item(&self, _cmd: DeleteItem)  -> Result<()>

What `provider-author-guide.md`'s trait sample claims:

    async fn create_event(&self, cmd: CreateEvent) -> Result<Event>
    async fn update_event(&self, cmd: UpdateEvent) -> Result<Event>
    async fn delete_event(&self, cmd: DeleteEvent) -> Result<()>

`capabilities.md` also refers to `Handler::create_event` in prose.

## Severity is MEDIUM, not HIGH — and the reason matters
A method that is not a member of the trait is a hard compile error (E0407) inside
`impl Handler for T`, and `CreateEvent`/`UpdateEvent`/`DeleteEvent` no longer exist as type names.
The author is stopped loudly, which is the **intended C-16 outcome**. This is a documentation
defect that wastes an integrator's time and contradicts shipped code — not a silent-breakage
hazard. Do not describe it as one in the fix.

## Acceptance criteria
1. The trait sample in `provider-author-guide.md` matches `caldir-core/src/provider/handler.rs`
   at HEAD exactly: method names, parameter types, and return types.
2. `capabilities.md`'s prose reference names the shipped method.
3. **C-16 is stated where the sample lives:** the Rust API is item-typed while the wire verbs stay
   `create_event`/`update_event`/`delete_event` with payload key `event`. An author who reads only
   the renamed sample must not conclude the wire changed. This is the substantive addition — the
   rename is otherwise mechanical.
4. No other content changes. The write lifecycle stays deferred to `P6-01`.
5. No `file.rs:NN` line-number citation is introduced (C-11).

## Non-goals
- No write-lifecycle documentation — that is `P6-01`, which continues these files.
- No code change of any kind.
