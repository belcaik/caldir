# W3-C2: Flip CalDAV `tasks.write` to honest per-remote reporting

**Needs:** P3-02 (`3ae3e1b`), P3-03, P3-04 (`737164c`) — **all three must be committed**
**Origin:** P3-04 correctly deferred the flip; no ticket owned it afterwards

## Why this exists as its own ticket
`P3-01` declared `tasks.write = true` before any write path existed. `W3-C1` (`ba93be7`) held it
`false`, pinned by `tasks_write_is_held_false_until_the_write_path_lands`. `P3-04` was offered the
flip and **correctly declined**: it checked `git log`, found `P3-03` had not landed as a commit,
and applied D-2 — `tasks.write = true` is legal only once create, update and delete are all
coherent. That judgment was right, and it left the flip unowned. This ticket owns it.

**This is the flag that lets core push tasks to real user calendars.** It gets its own commit and
its own scrutiny rather than riding along in a ticket about something else.

## Precondition — verify, do not assume
`git log --oneline` must show committed features for create (`P3-02`), update (`P3-03`) and delete
(`P3-04`). If `P3-03` is still uncommitted, **stop and report BLOCKED.** Do not flip against
uncommitted work in the tree; a green test run over someone else's unlanded edits proves nothing
about what ships.

## Acceptance criteria
1. `tasks.write` is reported **per remote**, driven by the same `caldav_supports_tasks` key in
   `RemoteConfigParams` that `tasks.read` already uses — following `W3-C1`'s exact shape.
2. **Fail closed (C-8).** Absent, unknown, or unreadable capability information reports
   `tasks.write = false`, never `true`. **Never hardcode `true`** — that is the defect `W3-C1`
   existed to fix, and reintroducing it here would undo that fix.
3. `tasks_write_is_held_false_until_the_write_path_lands` is replaced deliberately, not deleted.
   Its successor asserts the new contract: a task-capable remote reports `true`, and every
   fail-closed input still reports `false`. **Do not weaken it into vacuity** — the same standard
   `P2-01` was held to when it inverted its two locks.
4. A remote whose collection cannot serve tasks reports `tasks.write = false`, and the existing
   `tasks.read` fail-closed tests stay green, unmodified.
5. **C-14 must not regress:** `a_healthy_listing_never_asks_for_the_component_set` and
   `a_rejected_vtodo_report_does_not_break_an_event_only_listing` stay green, unmodified. Reporting
   a capability must fire **zero** extra requests.

## What flipping this actually turns on
With `tasks.write = true`, `P1-03`'s `TaskPushes::Allowed` stops withholding task changes and
`P2-01`'s dispatch sends them to this provider for real. Verify by reasoning, and say so in the
report, that create, update and delete each have a working `Todo` arm — not merely that they
compile.

## Non-goals
- No change to `tasks.read` — `W3-C1` settled it.
- No provider write logic — `P3-02`/`P3-03`/`P3-04` own that.
- Google's declaration is `P4-05`, which should follow this ticket's shape.
