## RED tests
- **ADD** `caldir_core_never_branches_on_a_provider_name` in a new integration test
  `caldir-core/tests/provider_neutrality.rs`. Scans every `.rs` under `caldir-core/src`, excluding
  `#[cfg(test)]` fixtures it names explicitly, for a word-bounded occurrence of any shipped provider
  slug (`caldav`, `google`, `icloud`, `outlook`, `webcal`) and asserts the offender list is empty.
  Right proof: `CROSS-2` is a *negative* about code that does not exist yet, so no behavioural test
  can catch its introduction — only a scan fails on the commit that adds the branch.
- **ADD** `no_caldir_core_path_converts_a_vtodo_into_a_vevent` in the same file. Asserts
  `CalendarItem::into_event` is the **only** narrowing from a task to an event in `caldir-core/src`
  — no `impl From<Todo> for Event`, no `Event::from_todo`, no `as_event` — by scanning for those
  shapes. Right proof: `CROSS-6` fails silently and destructively; a converted task looks like a
  successful push, so the guard has to be structural.
- **ADD** `item::tests::the_task_to_event_narrowing_stays_fallible_as_a_backstop` in
  `caldir-core/src/item.rs`. Asserts `CalendarItem::Todo(..).into_event()` returns `Err` and that the
  `Event` arm returns the same event unchanged. Right proof: `into_event`'s whole safety value is
  that it *cannot* succeed for a task — making it infallible would compile everywhere and silently
  satisfy every other test in the suite.
- **ADD** `remote::tests::a_task_write_produces_the_same_request_for_every_provider_slug` in
  `caldir-core/src/remote.rs`. Drives the same task create through `MockProvider::new("caldav")` and
  `MockProvider::new("google")` and asserts the two `captured_request` bodies are byte-equal. Right
  proof: it is `CROSS-1` and `CROSS-2` in one assertion — one core task type, and core's outbound
  bytes provably independent of who is listening.
- **ADD** `a_calendar_holding_events_and_tasks_pushes_both_and_exits_zero` in
  `caldir-cli/tests/push_exit_status.rs`, built on `event_ics` and `task_ics` against a task-capable
  stub provider. Asserts exit status `0`, both items in the RPC log, and the event half byte-identical
  to what `an_event_only_push_still_exits_zero_and_summarises_what_it_pushed` produces. Right proof:
  `CALDAV-8` and `GOOGLE-12` are "events still work" claims, and the only place a task write can break
  an event write is a shared calendar in a real push.

## Notes for the implementer
- **`grep` for `"caldav"` has exactly one legitimate hit today**, in `remote::config`'s own tests
  (`RemoteConfig::from_toml(r#"provider = "caldav""#)`). Allow-list it by path in the scan and say
  why in a comment; a scan that starts red is a scan people disable.
- **Reuse `scan_rust_sources` / `contains_word`.** They already solve the self-match problem —
  `deny_unknown_fields_appears_nowhere` assembles its needle with `concat!` and matches on word
  boundaries so its own name is not a hit. An integration test cannot import them (they are private
  `#[cfg(test)]` helpers in `rpc.rs`); re-implement the same twenty lines rather than inventing a
  looser matcher.
- **`into_event` must stay fallible.** Its doc comment calls it *"a backstop, not the path a user
  travels"* and warns that *"pushing a task as an event would be a silent corruption, and dropping it
  would be a silent data loss, so the narrowing has to stay fallible."* After `P1-04`/`P2-01` a task
  reaches providers through the item-typed boundary and `into_event` should be unreachable in the
  task path — **do not delete it**; an unreachable backstop that would catch a future regression is
  the point.
- **`a_task_change_aborts_instead_of_reaching_the_provider` and its `_delete_` sibling are gone or
  inverted by `P2-01`.** Read the inverted versions before writing the CROSS-1 test; do not restore
  the old assertions.
- The `caldir-cli/tests/sync_exit_status.rs` `Fixture` builder (`with_provider`, `rpc_log`,
  `pushed_ids`) is the shortest path to a two-component push. `push_exit_status.rs` has its own
  simpler `event_ics`/`task_ics`/`make_executable` set — pick one harness and stay in it.
- **Do not cite a line number** (C-11).
