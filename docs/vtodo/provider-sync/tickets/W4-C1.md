# W4-C1: Surface the Tasks-scope degrade instead of swallowing it

**Needs:** P4-02 (`d8ed77f`), P4-03 (`43ccd22`) · **Origin:** orchestrator verification, MEDIUM

## The defect
`caldir-provider-google/src/commands/list_calendars.rs`:

```rust
if session.require_tasks_scope().is_err() {
    return Ok(Vec::new());
}
```

`P4-02` built `require_tasks_scope()` precisely so a session predating the Tasks scope produces an
**actionable reauthorization instruction** — naming the account and the exact command — rather than
a bare Google 403. `P4-03` then discarded that message with `.is_err()`.

The result: a user who reruns `caldir connect google` to get their task lists sees **no task lists
and no explanation.** The message exists, is tested, and never reaches anyone.

## Why degrading is still right
Hard-failing discovery would be wrong — a user who only wants calendars should not be blocked by a
missing Tasks scope. The degrade is correct; **silently discarding the reason is not.**

This is not a data-loss defect: `list_calendars` is discovery and does not drive deletion. It is an
observability defect, and it lands on the single path where the scope problem first becomes visible.

## Acceptance criteria
1. When the Tasks scope is missing, discovery still returns calendars and does not fail.
2. The reason reaches the user, carrying what `require_tasks_scope()` already produces: the account
   and the remedy. A `warning:` line on stderr matches the precedent
   `caldir-provider-caldav/src/caldav/ops/list_events.rs` sets for a degraded listing.
3. A test pins that the message is emitted and names both the account and the command. Assert on
   content, not on the fact that something was printed.
4. A session **holding** the scope emits no warning. Pin that too — a warning that always fires is
   noise, and noise is ignored.
5. Distinguish the two degrade causes if practical: a missing scope is a user-fixable state; a
   Tasks API failure is not. Do not report the second as the first.

## Non-goals
- No change to `require_tasks_scope()` itself — `P4-02` is done and its tests stay green.
- No capability declaration — `P4-05`.
- No hard failure of `list_calendars`.

## Minor, fold in while here
`caldir-cli/Cargo.toml` pins `toml = "1"` as a dev-dependency while `caldir-core` pins `1.1.2`.
Semver-compatible and harmless; align it for consistency if it costs nothing.
