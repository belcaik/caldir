# W6-C1: Remove internal ticket references from shipped code

**Needs:** all code-changing tickets complete · **Origin:** P3-03 discovery, confirmed by measurement
**Run:** immediately before `P6-06`/branch finish, so nothing re-introduces them afterwards

## The defect
Commit `200c8a8` ("docs: remove internal ticket references from shipped code") established that
shipped code carries **zero** internal ticket identifiers. The provider-sync effort reintroduced
them at scale.

Measured across non-test regions of tracked `.rs` files: roughly **50 occurrences in ~15 files** —
`C-8` (7), `C-16` (7), `CROSS-6` (6), `C-6` (4), `P4-03` (4), `P4-04` (3), `C-14` (3), plus
`W2-C3`, `S3`, `GOOGLE-13`, `CALDAV-*`, and assorted `P*-**`. Worst files: `test_utils.rs`,
`provider/handler.rs`, `google_tasks/from_google.rs`, `caldav/commands/capabilities.rs`,
`diff/calendar_diff.rs`, `connection.rs`.

This is a process artifact: implementer briefs asked agents to cite the binding corrections, and the
citations landed in production doc comments.

## Why it matters
These identifiers resolve only against `docs/vtodo/provider-sync/tickets/`, which is internal
planning material. An upstream reader — or the out-of-tree Proton author — hits `C-8` in a doc
comment with no way to look it up. The convention exists because unresolvable references are worse
than no reference.

## The rule — keep the reasoning, drop the label
**The rationale in these comments is valuable and MUST survive.** Only the identifier goes.

- Before: `// Fail closed (C-8): an absent capability reads as false.`
- After: `// Fail closed: an absent capability reads as false.`

Do **not** delete a comment merely because it contains an identifier — that would discard exactly
the "why" the codebase wants. If a comment is *only* a bare citation with no explanation
(`// C-16`), replace it with the one-line reason it stood for, or remove it if it says nothing.

## Scope
- **In scope:** non-test regions of tracked `.rs` files across every crate.
- **Out of scope:** `#[cfg(test)]` blocks and test names. Existing convention already tolerates
  identifiers there, and shipped tests are read alongside the plan. Confirm against the tree's
  existing style rather than assuming.
- **Out of scope:** everything under `docs/`. That is where the identifiers belong.
- RFC references (`RFC 5545`), requirement numbers from the shipped core spec (`R92`), and standard
  property names are **not** internal ticket references. Leave them.

## Acceptance criteria
1. A grep for `P<n>-<nn>`, `W<n>-C<n>`, `C-<n>`, `S<n>`, `CROSS-<n>`, `CALDAV-<n>`, `GOOGLE-<n>`
   over non-test regions of tracked `.rs` files returns nothing. Include the grep in the report.
2. Every touched comment still explains *why* the code is shaped as it is. Spot-check the worst
   files by hand and show before/after for at least five.
3. No behaviour change whatsoever. `git diff` touches comments only — **zero** changes to
   executable lines.
4. `cargo fmt --check`, `cargo clippy --workspace --all-targets`, `cargo test --workspace` all green,
   with the test count unchanged from before the sweep.

## Non-goals
- No rewording beyond removing the identifier and repairing the sentence.
- No new comments.
- No doc-file changes.
