# L8-04 — semver bump and dependant pins (C11)

## Responsibility

`caldir-core`'s Rust API changed breakingly (pre-1.0, allowed). Bump core's minor version, bump all six
dependants, and update every `caldir-core = { path = "…", version = "…" }` pin to match.

## Requirements satisfied

- **C11** (SOFT, `spec.md` §15): *"`caldir-core` Rust API — Semver-breaking changes allowed (pre-1.0) but
  require a minor bump, matching bumps of all six dependants, and their `version = "…"` pins updated."*

The breaking changes this bump accounts for: `Event::from_ics_str` returns `Vec<Result<CalendarItem, _>>`
and `from_single_ics_str` returns `CalendarItem` (`L2-06`); `CalendarEvent::event()` narrows to
`Option<&Event>` (`L2-06`); `Calendar::events()` returns a listing struct rather than `Result<Vec<_>>`
(`L0-01`); `EventInstanceId` carries a `ComponentKind` (`L1-06`); the `rpc::methods` typed fields carry
`CalendarItem` (`L4-02`).

## Dependencies

`L5-05`, `L6-01`, and **all** `L7-*`. In practice: everything that can still change a public signature must
be merged first, or the bump is computed against a moving API.

## RED tests

**None.** Verification is `cargo check --workspace` plus a packaging dry-run.

## Acceptance criteria

1. `caldir-core` receives a **minor** bump (0.14.x → 0.15.0), not a patch. The API break is real.
2. All **six** dependants are bumped: `caldir-cli` and the five `caldir-provider-*` crates.
3. Every `caldir-core = { path = "../caldir-core", version = "…" }` pin equals core's **new** version.
   Grep proves it; do not eyeball it.
4. Workspace `Cargo.toml` is consistent (members list unchanged — no new crate ships in this feature).
5. `cargo check --workspace` clean and `cargo package -p caldir-core --dry-run` succeeds.
6. `Cargo.lock` is regenerated and committed if the repo tracks it.
7. `just test` green after the bump.

## Notes for the implementer

- **Trap — patch instead of minor.** Pre-1.0 semver lets a `0.x` minor carry breaks, and C11 *requires* the
  minor. A patch bump silently ships an API break to any consumer using a caret requirement — the exact
  failure mode ADJUDICATION C-3 documents from the `icalendar` probe (a caret requirement resolved 0.17.13
  while the probe claimed 0.17.10, producing a wrong answer).
- **Trap — forgetting a pin.** Path dependencies resolve locally, so a stale `version = "…"` pin builds
  fine in the workspace and breaks only at publish time. The grep in Verification is the guard.
- **Trap — bumping mid-feature.** If any `L5-*`/`L6-*`/`L7-*` ticket is still open, stop. The version must
  describe a settled API.
- Never run two cargo commands in parallel (rustup toolchain race, `docs/vtodo/context/testing.md` §1).
  Toolchain is pinned to `1.97.0`.
