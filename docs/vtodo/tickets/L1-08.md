# L1-08: VEVENT no-regression control lock

**PR-2.** **Tests only — this ticket adds no production code.**

## Responsibility
Lock R2/C2 at the end of the L1 layer: now that `Todo` exists and the equality helpers have moved,
prove that an existing VEVENT still parses to a structurally `==` event, re-serializes
byte-identically (modulo the always-re-stamped `DTSTAMP`), and that `occurs_in_range` is unchanged.

## Requirements satisfied
- **R1 (INVIOLABLE)** — *"caldir MUST NOT convert a VTODO into a VEVENT or vice versa at any layer — disk, domain, sync base, RPC wire, provider. No synthesized `DTSTART`, no synthesized `DTEND`, no fake-event representation of a task anywhere."*
- **R2 (INVIOLABLE)** — *"VEVENT behaviour MUST NOT change observably: same bytes, filenames, parse result, equality, sync direction, text output (§15 C1/C2/C13)."*
- **R45** — *"The event predicate `occurs_in_range` (`event.rs:136-141`) MUST be unchanged, byte for byte (R2)."*
- **R104 (INVIOLABLE)** — *"The 686-test baseline MUST stay green in all three CI timezones with **zero edits to existing event tests**. Any required edit to an existing event test is a design failure, not a fixup."*
- **C2 (INVIOLABLE)** — *"An existing VEVENT file parses to a structurally `==` event before and after; event equality unchanged."*

## RED tests
- **ADD** `event::tests::vevent_control_round_trips_identically_after_vtodo_support` (**T-5**,
  R2/R104) in `caldir-core/src/event.rs`'s test module. **TZ-marked (R106).** It MUST assert, for a
  representative VEVENT corpus (at minimum `VEVENT_CONTROL_ICS`, plus an all-day event, a recurring
  master, and one carrying `X-` properties and an attachment — the fields `L1-02` touched):
  1. parse → serialize → parse yields an event `==` the first (structural equality, C2);
  2. the serialized bytes are identical to the input **after stripping `DTSTAMP`** — reuse
     `strip_dtstamp` at `event.rs:1112`;
  3. `occurs_in_range` returns the same answers at both edges of a range as it does today.
  Why this is the right proof: R2's failure mode is not a compile error. Equality drift changes sync
  *direction*; a serialization drift rewrites every user's files on next write; a predicate drift
  changes what gets deleted. Each of the three is separately invisible, so each is asserted
  separately.
- **KEEP GREEN, UNEDITED**: the entire existing event test suite, and the Stage-2 control tests
  `event::tests::from_single_ics_str_parses_the_vevent_control_document` (`event.rs:1163`),
  `calendar::tests::events_lists_the_vevent_control_file` (`calendar.rs:1186`),
  `caldir::tests::vevent_calendar_lists_independently_of_a_sibling_vtodo_calendar` (`caldir.rs:407`).

- **Do not** touch `event/slugify.rs` — filename locking is T-6 in `L1-07`.

## Notes for the implementer
- Byte comparison is legitimate **here** and only here: this is a local disk round trip, not a wire
  round trip. R30's ban on raw-byte comparison applies to gates that compare what caldir PUT against
  what a **server** returns (Radicale re-sorts properties and re-folds lines). Do not carry a byte
  assertion into any provider-facing test.
- `DTSTAMP` is re-stamped on every serialize (R25), so an unfiltered byte comparison is permanently
  red. Use the existing `strip_dtstamp`.
- Pick corpus events that exercise the fields `L1-02` moved — `x_properties` (order-independent, with
  parameters that are *ignored* by `XProperty`'s `PartialEq`) and `attachments` (compared by URI
  only). A corpus without them cannot detect the regression this ticket exists to catch.
- TZ-marked because `EventTime` handling and `to_local_tz` are zone-sensitive; use the `TZ3` loop, not
  a single run.
- Conventions: inline `#[cfg(test)] mod tests`, no fixture files,
  `use pretty_assertions::assert_eq;`. CI: `-D warnings` on `just check`.
