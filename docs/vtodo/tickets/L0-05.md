# L0-05: event_by_instance_id must distinguish "absent" from "unreadable"

## Responsibility
Close the absence-inference hole that PR-1's graceful degradation opened in
three `pub` core APIs. R48's guard was applied to `CalendarDiff` only; the
same faulty inference is now live in `Calendar`.

## Why this is a real bug (found by the PR-1 adversarial review, MAJOR-1)
`Calendar::event_by_instance_id` now returns `Ok(None)` for an event whose
file EXISTS but is UNREADABLE. Before PR-1 it returned `Err`. Consequences:

1. `Calendar::update_recurring_instance` reads `None` as "no override exists
   yet", synthesizes one from the master, and calls `create_event` ->
   `write_best_event_file` allocates a UNIQUE filename, so it does not
   clobber: it writes a SECOND file for the same (uid, recurrence_id).
   Two files, one instance, silently. `doctor` CANNOT see it —
   `duplicate_file_warnings` only compares `listing.events()`, and the
   unreadable twin is not in there.
2. `Calendar::split_recurring_series_at` — if an override's file is
   unreadable, the split writes the new master but silently never re-points
   that override. Previously the whole operation aborted BEFORE writing.
   Fail-loud became half-complete.
3. `Calendar::delete_recurring_instance` — adds the EXDATE to the master and
   leaves the unreadable override orphaned. Previously it errored.

R48's own justification is "no absence in an incomplete listing proves
anything." That is exactly as true here as in `calendar_diff.rs`.

## Severity
Not CLI-reachable today (grep: only tests call these three). But
`caldir-core` IS published to crates.io (release.yml runs `cargo publish`,
currently 0.14.1) and CLAUDE.md says GUIs consume it directly. So: a live
`pub` API contract regression, currently untested.

## Acceptance criteria
1. `event_by_instance_id` distinguishes "not present" from "present but
   unreadable". Cheapest honest shape: return an error (or a three-state)
   for the unreadable case rather than `Ok(None)`.
2. All three call sites handle the unreadable case WITHOUT writing:
   no duplicate file, no half-complete split, no orphaned override.
3. A test per call site proving the pre-PR-1 fail-loud behaviour is restored.
   Each must FAIL before the fix.
4. `doctor` still reports the skipped file (do not regress R77).
5. Zero regressions; RED VTODO five still fail for their original reason.

## Non-goals
- Do not touch `CalendarDiff`'s R48 guard; it is correct.
- Do not add a user-facing warning surface (that is MAJOR-2's question).
