# L0-03: C7 guard — a calendar with any unreadable file emits zero deletes

**PR-1, and the reason PR-1 exists.** `L0-01`, `L0-02` and this ticket MUST land together. R6:
graceful degradation ships first as its own change **and that change MUST include R48**. Shipping
`L0-01` (a core that silently skips a file it cannot parse) without this guard, against a
VTODO-aware provider, makes caldir **delete the user's tasks server-side**. Do not let this ticket
slip out of the PR.

**PR-1 turns NONE of the five VTODO RED tests green.** Its exit criterion is `T-29` plus the
unmodified 686-test baseline — never "the reproduction passes".

## Responsibility
Thread the "this listing is incomplete" signal from `L0-01` into diff computation and, when it is
set, suppress **every** delete for that calendar on that sync — outgoing and incoming alike. Creates
and updates are unaffected.

## Requirements satisfied
- **R48 (INVIOLABLE)** — *"If any `.ics` file in a calendar failed to load, that sync MUST emit **zero** deletes for that calendar, in either direction. Without it, a gracefully-degrading core paired with a VTODO-aware provider reaches `calendar_diff.rs:110` with the task present remotely, absent locally (file skipped) and its base known — and deletes the user's task server-side."*
- **R74** (the "fix for A must not create B" clause) — *"Both MUST be fixed, and the fix for A MUST NOT introduce B. A is fixed by per-file graceful degradation plus R48…"*
- **C7** (INVIOLABLE) — *"R48: a calendar with any unreadable file emits zero deletes that sync."*

## Dependencies

## RED tests
- **ADD** `diff::calendar_diff::tests::unreadable_local_files_suppress_all_deletes`
  (**T-29**, spec §18, R48/C7) in `caldir-core/src/diff/calendar_diff.rs`'s test module.
  It MUST construct the exact hazard shape and assert zero deletes in **both** directions:
  1. a remote item present, absent locally, **with a known base** — the `:110` path that would
     otherwise emit an outgoing `Delete`;
  2. a local item present, absent remotely, with a known base — the `:86` path that would otherwise
     emit an incoming `Delete`;
  3. the listing marked incomplete (at least one skipped file);
  then assert `diff.outgoing()` and `diff.incoming()` contain **no** `EventChange::Delete`.
  It MUST also assert that a create/update in the same run is **still emitted**, so the guard is
  proved to be delete-scoped and not a blanket "do nothing".
  Why this is the right proof: R48 names both directions and the base-known precondition; a test
  that only covers one direction leaves the other half of the INVIOLABLE requirement unguarded.
- **KEEP GREEN, DO NOT EDIT**: every existing `calendar_diff` and `connection` test. If an existing
  delete test starts failing, your signal is defaulting to "incomplete" — that is a bug, not a fixup.

## Acceptance criteria
1. `CalendarDiff::compute` (or the seam feeding it) receives the incompleteness signal from the
   calendar listing rather than inferring it. (R48, Q-6)
2. When the signal is set, **zero** `EventChange::Delete` values appear in `outgoing()` or
   `incoming()`. (R48, C7)
3. When the signal is clear, delete behaviour is byte-for-byte what it is today — all existing
   delete tests pass unmodified. (R2, R104)
4. `unreadable_local_files_suppress_all_deletes` passes. (T-29)
5. `just check` and `just test` (686 baseline) green, zero edits to existing event tests. (R104)

## Non-goals
- **Do not** implement R49 (the "remote returned zero tasks" skew belt). That is `L3-04`, keys on a
  different signal, and is scoped to *task* deletes only.
- **Do not** add tasks, `CalendarItem`, or kind-aware diff keying (`L3-03`). This guard is
  kind-agnostic: it suppresses **all** deletes for the calendar.
- **Do not** touch direction machinery — three-way-against-base first, mtime/`LAST-MODIFIED`
  fallback, the Push-biased `(Some, None)` rule at `calendar_diff.rs:187` (R40, R41).
- **Do not** touch the window predicate `has_occurrence_in_range` / `occurs_in_range`
  (`event.rs:136-141`) — R45 requires it byte-identical, and R44's task rule is `L3-02`.
- **Do not** add a user-facing warning for the suppression (C13; the *skip* is required, the *text*
  is not).

## Notes for the implementer
- **Polarity trap.** Default MUST be "listing complete ⇒ deletes behave exactly as today". Any code
  path that constructs a diff without an explicit signal (tests, `Connection`, future callers) must
  land on the permissive-delete side, or you silently disable delete propagation for every user.
  R47 makes the same point about the window predicate: this class of boolean is easy to state
  backwards, so assert both polarities in the test.
- Suppress at the point the `Delete` is pushed (`:86-90`, `:110-116`), not by post-filtering a
  finished diff, if post-filtering would also strip deletes that a caller constructed directly via
  `CalendarDiff::from_changes` (`test_utils.rs:106-128`) — those constructors are used by existing
  tests and must keep working.
- `Connection::diff` is the only production caller of `compute` (`connection.rs:55`); it already has
  the listing in hand at `:38`. Keep the plumbing one value wide — no config, no builder (R73/R91).
- Conventions: inline `#[cfg(test)] mod tests`, no fixture files, `use pretty_assertions::assert_eq;`,
  bind every `TempDir`.
- CI: `just check` with `RUSTFLAGS: -D warnings`; `just test` under `TZ` = `UTC`,
  `Europe/Stockholm`, `America/New_York`.
