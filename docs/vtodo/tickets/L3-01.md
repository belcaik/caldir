# L3-01 — sync state carries tasks

> Layer L3 (sync engine) · PR-2 · from `docs/vtodo/tickets/INDEX.md` §1.
> **Advisory same-commit pair with `L1-06`** — see §Dependencies.

## Responsibility

Make `.caldir/state/` hold tasks as well as events:

1. `bases/<sha256(identity_string)>.ics` may hold a single-component `BEGIN:VTODO` body.
2. `EventBases` and `SyncBases` key by the **kind-carrying** identity from `L1-06`, so an
   event and a task sharing a UID get two distinct base files and two distinct map entries.
3. An unparseable base is still **skipped, not fatal** — the C5 downgrade path is preserved
   byte-for-byte in behaviour.
4. The base decoder applies the **R18 `VTIMEZONE` exemption**, exactly like the disk loader.

The on-disk *layout* does not change: same `bases/` directory, same sha256 hex filename, same
single-component `VCALENDAR` documents, same `known_event_ids` file.

## Requirements satisfied

- **R43.** *"Task sync bases MUST use the existing layout unchanged: a single-component
  `VCALENDAR` at `bases/<sha256(identity_string)>.ics`. Hard dependency on R32/R19 — until the
  arity rule can return a task, a task base loads as zero components and is silently skipped,
  degrading every task to a legacy known-id entry and permanently disabling the three-way
  compare."*
- **R18** (base-decoder half). *"`VTIMEZONE` MUST be ignored for counting and MUST NOT be
  treated as unsupported — **on the wire and sync-base decoder as well as the disk loader**."*
- **R76.** *"The wire/sync-base error type needs the arity variant and SHOULD NOT duplicate the
  'none' variant: bases are always written by caldir, and the wire case is covered by R19."*
- **C5 (INVIOLABLE).** *"An old caldir MUST skip, not fail on, a base it cannot parse (the
  `else { continue }` at `event_bases.rs:60-62`). The hash-filename scheme MUST NOT change;
  bases stay single-component VCALENDAR documents."*

## Dependencies

- **`L1-06`** — `EventInstanceId` carries `ComponentKind`; string form `VTODO:{uid}[__{rid}]`.
- **`L2-06`** — the loader can return a `CalendarItem`; without it a task base decodes as zero
  components (R43's stated hard dependency).
- **Advisory (INDEX §5, not spec-mandated): ship in one commit with `L1-06`.** The identity
  string form and the `bases/` + `known_event_ids` layout are two halves of **one on-disk
  contract**. Landing the sigil without rehashing bases leaves a state directory whose
  filenames no longer match their contents. It is recoverable — bases degrade to "no base" —
  but it costs every user a full re-sync. Say so in the commit message if they are split.

## RED tests

**`T-23`** — `calendar::state::event_bases::tests::a_task_base_loads_and_rehashes_and_an_unparseable_base_is_skipped`
in `caldir-core/src/calendar/state/event_bases.rs` (inline `#[cfg(test)] mod tests`).

Asserts, in one test, the three things that can independently break:

1. **Task base round-trips.** `EventBases::write_from([&task_item], dir)` then
   `EventBases::load(dir)` returns exactly one entry whose key is the *task* identity (kind
   `Todo`) and whose value is structurally `==` the task. *Why:* proves the base file holds a
   `BEGIN:VTODO` body and the arity rule accepts it (R43).
2. **Rehash agrees.** The loaded entry survives the `filename == expected_filename` check —
   i.e. `hash_filename(loaded.event_instance_id().to_string())` reproduces the on-disk name.
   *Why:* this check silently discards any base whose id string form drifted; it is the exact
   mechanism that makes `L1-06` + `L3-01` one contract.
3. **Unparseable base is skipped, not fatal.** Writing `"not an ics file"` and `""` into two
   extra correctly-named hashed files leaves `load()` returning `Ok` with only the good
   entries. *Why:* C5, INVIOLABLE.

Extend the existing `sync_bases::tests::corrupt_base_degrades_to_known_id_entry` coverage only
if it fails to compile; do not weaken it.

## Acceptance criteria

1. `EventBases` stores and returns `CalendarItem` (or an equivalent kind-carrying value), not
   `Event`; `SyncBases`'s map value type follows.
2. A task and an event sharing one UID produce **two** base files with **different** sha256
   filenames, and **two** distinct `SyncBases` entries.
3. A base document containing `VTODO` + a sibling `VTIMEZONE` decodes successfully (R18).
4. A base document containing an unsupported data-bearing component, or two supported
   components, produces an error that is **caught and skipped** by `load()` — never propagated.
5. `hash_filename` is unchanged; `is_hashed_filename` is unchanged; the `bases/` directory name
   and `.ics` suffix are unchanged (C5).
6. The base error type gains the arity variant and does **not** gain a duplicate "none"
   variant (R76).
7. `write_from`'s parse-compare skip (`event_bases.rs:34`) still skips unchanged bases despite
   `DTSTAMP` drift, for tasks as well as events — the existing
   `write_skips_unchanged_bases_despite_dtstamp_drift` test stays green and gets a task twin
   only if it is cheap.
8. `T-23` exists with exactly the name above and passes.
9. `SUITE` (686-test baseline) is green with **zero edits to existing event tests** (R104).

## Non-goals

- Any change to the window predicate or delete inference — that is `L3-02` / `L3-03`.
- Any change to the `known_event_ids` line format — that is `L1-06` (`T-21`).
- Any state-format migration tooling. Bases that fail the rehash check degrade to "no base";
  that is the accepted cost, not a bug to fix here.
- Any provider-crate edit.

## Notes for the implementer

- **`Event::load_single` is the seam.** Both the write-skip (`:34`) and the load path (`:60`)
  call it. After `L2-06` the item-typed equivalent is what you want; keep the `is_ok_and`
  shape so a failed parse still means "rewrite the base", never "abort".
- **Trap — the rehash check is a silent discarder.** `event_bases.rs:66` inserts only when the
  recomputed filename matches. If `Display for EventInstanceId` changes for a kind and the file
  was written under the old form, the base is dropped without a message. That is the intended
  degradation, but it means a *bug* in the sigil is invisible here — which is why `T-23`
  asserts the rehash explicitly rather than only asserting `load()` returned something.
- **Trap — `SyncBases::record` writes both formats** (`sync_bases.rs:58`, `:61`): the legacy
  `known_event_ids` file *and* the `bases/` directory. Both must receive the kind-carrying id,
  or delete detection and the three-way compare disagree about the same item.
- `test_utils.rs` is `#[cfg(test)] mod test_utils;` and **crate-private** — usable from
  `caldir-core` tests only, never from `caldir-cli` or a provider crate.
- Inline ICS string literals with explicit `\r\n`; no fixture files, no `tests/` directory.
