# L2-08 — `doctor` duplicate detection is kind-aware

**Layer:** L2 · **PR-2** · **Depends on:** `L1-06`, `L2-04`

## Responsibility

An event/task pair sharing a UID is **two legitimate files**, not a duplicate. Make `doctor`'s
duplicate-file detection bucket by the kind-carrying identity so it stops telling the user to
delete one of two correct files.

This is R36 hazard 5 — the only one of the five identity hazards that lands in the CLI.

## Requirements satisfied

- **R36 (INVIOLABLE), hazard 5** — "**`doctor` false positive** — duplicate detection buckets by
  identity (`doctor/warning/duplicate_file.rs:14-20`) and tells the user to delete one of two
  legitimate files." R36's fix: "Item identity MUST carry the component kind:
  `(kind, uid, Option<recurrence_id>)`. A component-agnostic key is not acceptable."
- **R4 (supporting)** — "One local calendar directory MAY hold both kinds, including a same-UID
  pair. Supported, non-error local state."
- **C13 (INVIOLABLE, constraint)** — "Existing text for existing situations unchanged." A genuine
  duplicate must still produce the **identical** warning text it produces today.

## Required context

- `spec.md` §10 R36 (the five hazards; hazard 5 is yours) and §2 R4.
- `adr/ADJUDICATION.md` §C-1 — the ruling that `EventInstanceId` gains `ComponentKind`, including
  the explicit citation of `doctor/warning/duplicate_file.rs:14-20`. ADR-01 decision #7 is STRUCK.
- `L1-06`'s ticket — `EventInstanceId` already carries `ComponentKind` and its string form is
  `{uid}` / `{uid}__{rid}` for events and `VTODO:{uid}` / `VTODO:{uid}__{rid}` for tasks (R37).
- `context/testing.md` §6 (`indoc!` for expected CLI text) and §1 (`-D warnings`, TZ matrix,
  never parallel cargo).

| `commands::doctor::warning::duplicate_file::tests::an_event_task_uid_pair_is_not_a_duplicate` (**T-22**) | `caldir-cli/src/commands/doctor/warning/duplicate_file.rs` (test module) | given a calendar holding one VEVENT file and one VTODO file **sharing a UID**, `duplicate_file_warnings` returns **zero** warnings | It is the exact user-visible shape of hazard 5: a legitimate mixed directory. Pair it with a control in the same module asserting that **two genuine same-kind duplicates still

## Acceptance criteria

1. `duplicate_file_sets` buckets on the kind-carrying `EventInstanceId` from `L1-06`. (R36)
2. `T-22` passes: an event/task same-UID pair produces zero `DoctorWarning::DuplicateFiles`.
   (R36 hazard 5, R4)
3. Two same-kind files sharing an identity still produce exactly one warning, with the existing
   text unchanged. (C13)
4. Two tasks sharing a UID (both `VTODO:`-prefixed) are still a duplicate — the fix
   distinguishes kinds, it does not exempt tasks. (R36)
5. `just check` clean under `-D warnings`; `cargo test -p caldir-cli -- duplicate_file` green;
   `just test` green at 686 + new tests.

## Non-goals

- **Do not** touch the other four R36 hazards. Hazards 1–4 (state-file collision, diff
  mis-keying, wrong-component deletion, base-file overwrite) are `L3-01`/`L3-03`; they close
  through `L1-06`'s identity change, not through `doctor`.
- **Do not** add a new `DoctorWarning` variant — no "mixed kinds" advisory, no new renderer.
  Nothing in §15 or §16 asks for one and it would be new CLI text (C13).
- **Do not** touch `DoctorWarning::UnreadableEvents` (`doctor.rs:55-57`) — that is `L0-02`
  and `L7-05` (R77, `T-43`).
- **Do not** change `EventInstanceId` itself. `L1-06` owns it; if the kind axis is missing,
  `L1-06` has not landed and you are blocked, not authorised to add it.
- **Do not** implement the R32 "mixed-component file" doctor warning ADR-03 §Consequences muses
  about — no R-number covers it in this feature.

## Notes for the implementer

- Landmarks: `duplicate_file_warnings` at `caldir-cli/src/commands/doctor/warning/duplicate_file.rs:6`;
  the `HashMap<EventInstanceId, Vec<PathBuf>>` bucketing loop at `:13-20`, with
  `ce.event().event_instance_id()` at `:18`. After `L2-04` that call reads through `item()` /
  `as_event()`; after `L2-06`, `event()` is `Option<&Event>` — take the identity from the **item**,
  not from a narrowed `Event`, or tasks vanish from the check entirely.
- If `L2-06` has landed, a `filter_map(as_event)` here would silently exclude every task from
  duplicate detection. That looks like a pass and is a regression: two duplicate tasks would go
  unreported. Bucket the items, do not narrow them.
- The accepted residual on the sigil (ADJUDICATION B-4): a VEVENT whose UID literally begins with
  `VTODO:` round-trips as a task. Do not add a workaround — it is the same ambiguity class
  already accepted for `__` at `instance_id.rs:38-40`, and no encoding removes it.
- `caldir-core/src/test_utils.rs` is `#[cfg(test)]` and **not exported** (`lib.rs:11-12`), so this
  CLI test must build its own fixture files locally (write two `.ics` strings into a `TempDir`).
- CI runs the CLI suite under `UTC`, `Europe/Stockholm`, `America/New_York`. Keep the fixture's
  times floating or date-valued so the test is TZ-neutral (`context/testing.md` §7.11).
