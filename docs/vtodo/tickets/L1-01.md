# L1-01: the `Todo` struct and `TodoStatus`

**PR-2.** PR-1 (`L0-01`/`L0-02`/`L0-03`) must have landed first.

## Responsibility
Introduce `pub struct Todo` carrying exactly the MVP field set (ADR-01 #3 **as amended by
ADJUDICATION C-2 and C-4**) and a **distinct four-valued** `TodoStatus`. Types and constructors only:
no ICS codec, no `PartialEq`, no filename slug, no window predicate, no `end`, no `availability`.

## Requirements satisfied
- **R7 (INVIOLABLE)** — *"An item's kind is determined solely by the component it was parsed from and is preserved across every boundary: disk, base, wire, provider, server."* (domain half: a task is its own type, never an `Event`)
- **R8** — *"A task MUST NOT carry `DTEND` or `DURATION`. RFC 5545 §3.6.2 forbids `DTEND` in a VTODO, and `icalendar` 0.17.10 emits one via the leaked `EventLike::ends()`…"* (satisfied **structurally**: no `end` field exists to emit from)
- **R9** — *"A task MAY have `DTSTART`, `DUE`, both, or neither. All four are first-class; none may be normalized away or given a synthesized value (R46)."*
- **R13** (field set) — *"The task type MUST model exactly the IN set and MUST NOT model the OUT set."*
- **R93** — *"**VJOURNAL.** Out of scope, but the design MUST NOT preclude it: adding it later should be one enum variant, one struct, one match arm — no second redesign."*

## Dependencies
none.

## RED tests
- **ADD** `todo::status::tests::the_four_task_statuses_round_trip` in
  `caldir-core/src/todo/status.rs`. It MUST assert, for each of `NEEDS-ACTION`, `IN-PROCESS`,
  `COMPLETED`, `CANCELLED`, that the ICS string maps to its variant and back to the identical string,
  and that the default is `NEEDS-ACTION`. Right proof because the four values are the ones RFC 5545
  defines for VTODO; an off-by-one variant set (e.g. reusing the event `Status`) silently produces
  impossible values at every match site, which is exactly what spec §6's STATUS row rejects.
- No existing RED test goes green here.

## Acceptance criteria
1. `Todo` exists with exactly the §6 IN fields and **none** of the OUT ones. In particular there is
   no `end`, no `availability`, no `dtstamp`, no `categories`, no `related_to`, no `duration` field.
   (R13, R8, R25)
2. `DTSTART` and `DUE` are both `Option`, independently. Neither defaults to the other, and nothing
   in the type can fabricate a date. (R9, R46)
3. `TodoStatus` has exactly four variants, defaults to `NeedsAction`, and is a **separate** type from
   `crate::event::Status` — the event enum is not extended, renamed, or re-exported under a new name.
   (R13 STATUS row, R2)
4. `the_four_task_statuses_round_trip` passes.
5. Adding a future `VJOURNAL` would be one more struct alongside this one; nothing here is written as
   "event or not-event". (R93)
6. `just check` and `just test` green, 686 baseline unmodified. (R104)

## Non-goals
- **No codec.** `From<&icalendar::Todo>` / `to_ics_string` are `L1-03` / `L1-04`.
- **No `PartialEq`.** `L1-02` owns it, because it must be written against the *shared* equality
  helpers, not a local copy.
- **No `base_slug`/filename** (`L1-07`), **no identity kind** (`L1-06`), **no window predicate**
  (`L3-02`), **no `CalendarItem` enum** (`L2-01`).
- **Do not touch `Event`** in any way — not its fields, not its derives, not its ordering. R2/C2 are
  INVIOLABLE.
- Do not add `CATEGORIES` or `RELATED-TO` fields "for later" — both are OUT (R87, R88) and modelling
  them through the crate actively corrupts data.

## Notes for the implementer
- **Four variants means R14's branch is already chosen.** Spec R14 allows an unknown `STATUS` either
  to round-trip verbatim **or** to be dropped with the loss pinned by a test. A strictly four-valued
  enum forecloses the first option, so `L1-03` must implement "explicitly dropped, pinned by T-14".
  State that in your handoff so `L1-03` does not re-litigate it.
- `COMPLETED` must be able to hold a **floating** value (R22), so type it with `EventTime`, not
  `DateTime<Utc>`. `CREATED` / `LAST-MODIFIED` are `Option<DateTime<Utc>>` like `Event`'s.
- `PRIORITY` is `Option<u8>` **raw**: values above 9 are legal input and must survive. Never route it
  through `icalendar::Component::priority()`, which clamps to `0..=10` and returns `None` above
  (§6 PRIORITY row) — relevant to `L1-03`, but do not add a clamping constructor here either.
- `PERCENT-COMPLETE` is `Option<u8>` and IS compared by `==` (R39). Whether `None` and `Some(0)`
  should compare equal is **Q-4, open** — do not decide it here.
- Mirror `Event`'s derive shape (`Debug, Clone, Eq, educe::Educe`) but leave the `PartialEq` attrs
  for `L1-02`; if the crate will not compile without a `PartialEq`, coordinate — do **not** write a
  throwaway one that `L1-02` then has to unpick.
- Module layout: `caldir-core/src/todo.rs` + `caldir-core/src/todo/status.rs`, declared and
  re-exported from `caldir-core/src/lib.rs`, mirroring how `event.rs` / `event/status.rs` are wired.
- CI runs `just check` with `RUSTFLAGS: -D warnings` and `just test` under `TZ` = `UTC`,
  `Europe/Stockholm`, `America/New_York`.
