# L4-01 — the RPC ICS codec becomes item-typed

> Layer L4 (provider contract) · PR-2. One file: `caldir-core/src/rpc/ics.rs`.

## Responsibility

`rpc::ics` encodes and decodes a `CalendarItem` instead of an `Event`. The wire decoder applies
the **same** arity and unsupported-component rules as the disk loader — **including the
`VTIMEZONE` exemption**, because a Radicale response for any zoned task is a multi-component
`VCALENDAR` and counting the `VTIMEZONE` would make every timezone-bearing task fail to decode.

Decode failure must be **loud**. That loudness is the entire reason old core + new provider is
safe (R57): a VTODO payload fails the old `Vec<Event>` deserialization, one bad element fails
the whole vector, the call errors, and the sync aborts **before any apply**.

## Requirements satisfied

- **R54.** *"The wire decoder MUST apply the same arity and unsupported-component rules as the
  disk loader (R19, R32), **including the `VTIMEZONE` exemption** (R18)."*
- **R18** (wire half). *"`VTIMEZONE` MUST be ignored for counting and MUST NOT be treated as
  unsupported — **on the wire and sync-base decoder as well as the disk loader**. Radicale
  returns a sibling `VTIMEZONE` for any `TZID` (probe Q-C), so a real zoned task payload is a
  multi-component `VCALENDAR` on the wire; counting it there would make every timezone-bearing
  task from Radicale fail to decode."*
- **R57 (INVIOLABLE).** *"Old core + new provider MUST be safe *because* R19 holds … the call
  errors, and the sync aborts **before any apply**. The catastrophic variant is a silent drop,
  which makes the remote list arrive short and feeds the delete path. **Both directions hinge on
  one principle: unknown must be loud or quarantined, never forgotten.**"*
- **R102 (A-8).** *"A CalDAV response body containing a `VTIMEZONE` sibling plus one VTODO MUST
  decode successfully."*
- **C10 (INVIOLABLE).** *"Wire decode of an unknown component: R19 — hard error, never a silent
  drop or empty vec."*

## RED tests

Both in `caldir-core/src/rpc/ics.rs`'s inline `#[cfg(test)] mod tests`.

**`T-10`** — `rpc::ics::tests::a_vtimezone_sibling_does_not_break_vtodo_decode`.
Feeds a JSON string whose ICS payload is a `VCALENDAR` holding one `VTIMEZONE` **and** one
`VTODO` with a `TZID`-bearing `DUE`. Asserts decode succeeds and yields the task, with its TZID
intact. *Why:* R18/R102 — this is the shape every real zoned Radicale response has; an arity
rule that counts `VTIMEZONE` breaks 100% of them while every synthetic single-component test
still passes.

**`T-35`** — `rpc::ics::tests::decoding_an_unknown_component_errors_rather_than_dropping`.
Feeds a payload containing a `VJOURNAL` (or `X-FOO`) alongside a supported component. Asserts
decode returns an **`Err` naming the offending component** — not `Ok` with the item, not `Ok`
with an empty result. *Why:* R19/C10/R57 — a silent drop makes a remote list arrive short and
that is exactly what feeds the delete path.

Keep the existing `event_round_trips_through_ics_wire_format` test green (adapt accessors only).

## Acceptance criteria

1. `Ics` wraps a `CalendarItem`; `serialize` accepts an item, `deserialize` returns one.
2. Decode of a `VCALENDAR` with one supported component + any number of `VTIMEZONE`s succeeds.
3. Decode of a `VCALENDAR` with an unsupported data-bearing component returns `Err` whose
   message **names** that component.
4. Decode of zero supported components, and of two supported components, each return distinct
   errors (R75's vocabulary as reached through the wire type, R76: no duplicated "none" variant).
5. Encode emits exactly one supported component per document (R27) and CRLF throughout (R28).
6. The JSON on the wire is still a **plain string** — no object, no new field, no schema change.
7. `T-10` and `T-35` exist with exactly those names and pass.
8. `cargo test --workspace --no-fail-fast` is green (this type is reachable from every provider
   crate).

## Notes for the implementer

- **Trap — reusing the *event* arity rule verbatim.** The disk loader's rule already exempts
  `VTIMEZONE`; the risk is writing a *second*, wire-local counting loop that forgets it. Route
  the wire decoder through the same `CalendarItem` entry point rather than reimplementing it —
  R54 is literally "the same rules".
- **Trap — `map_err(serde::de::Error::custom)` flattens your message.** `deserialize` at `:32`
  converts the parse error into a serde error string; make sure the component name survives that
  conversion, because `T-35` asserts on it and so does every human debugging a skew failure.
- **Trap — `Ics` is also used for response values**, not only `#[serde(with = ...)]` fields.
  Both paths must move together or one silently keeps the `Event` type.
- Do not add `#[serde(deny_unknown_fields)]` anywhere (R55/C9), and do not make any field
  non-`Option`.
- Fixtures are inline `\r\n` string literals; `test_utils.rs` is crate-private to `caldir-core`.
