# L5-04 — never PUT a multi-component `VCALENDAR`; a same-UID pair is a push error

**Layer:** L5 (CalDAV provider) · **PR-2** · **Depends on:** `L5-03`

## Responsibility

Two guards, one ticket. In the provider: structurally prevent a multi-component `VCALENDAR` from
ever reaching a PUT. In core: when a connected calendar holds a same-UID event/task **pair** and
both are outgoing to one collection, surface a **push error** instead of inventing an href scheme.
The local mixed directory itself stays fully supported.

## Requirements satisfied

- **R64 (INVIOLABLE)** — *"caldir MUST never PUT a multi-component `VCALENDAR`. Radicale answers
  `400 Bad Request` — server log: `Multiple component types in object: 'VEVENT', 'VTODO'`
  (probe Q-E.4)."*
- **R65** — *"A same-UID event/task pair cannot coexist in one CalDAV collection: Radicale enforces
  UID uniqueness per collection, component-type-agnostically — `409` across hrefs, `400` within one
  resource, silent `204` overwrite at the same href … caldir MUST surface a push error for a local
  same-UID pair rather than invent an href scheme. The local mixed directory (R4) stays supported;
  what is unsupported is pushing both to one collection."*
- **R80 (INVIOLABLE)** — *"caldir MUST never PUT a multi-component `VCALENDAR` (R64). An error-model
  rule as much as a serialization rule: the server answers `400`, and a retry loop would spin
  forever."*

## RED tests

1. `caldav::ops::tests::a_multi_component_vcalendar_is_never_put` **(T-41)**
   — in `caldir-provider-caldav/src/caldav/ops.rs`. Drive the guard with a hand-built document
   holding `VEVENT` + `VTODO` and assert it returns `Err` **and that no PUT reached the wiremock
   server** (`server.received_requests()` is empty / contains no `PUT`). Asserting only on the
   `Err` is insufficient: R64 is about the request never being sent, not about the error type.
2. `caldav::ops::tests::a_single_component_document_passes_the_guard`
   — one `VEVENT` and one `VTODO` document each pass, and a `VTIMEZONE` **sibling** plus one item
   also passes (R18 — Radicale returns exactly that shape and caldir may emit it, Q-3).
   Without this the guard bricks every zoned task.
3. `connection::tests::a_same_uid_event_task_pair_pushed_to_one_collection_is_an_error`
   — in `caldir-core/src/connection.rs` test module. Local calendar holds a VEVENT file and a VTODO
   file sharing a UID, both outgoing, one remote. Assert: `apply_outgoing_diff` returns `Err` naming
   the UID, **no** `CreateEvent`/`UpdateEvent` RPC was captured by the mock, and **both local files
   still exist unmodified**. Fails loudly before touching the network — a partial push here is the
   destructive case Radicale's `204` silent overwrite produces (probe Q-E.2).

## Acceptance criteria

1. A single helper in `caldir-provider-caldav` inspects the serialized ICS immediately before every
   PUT (`create_event.rs:33-39` and `update_event.rs:33-39`) and errors if it does not contain
   **exactly one** supported component; `VTIMEZONE` does not count toward the total (R18).
2. The error names both component types found, mirroring Radicale's own message shape, so the log
   is diagnosable without the server log.
3. Both PUT sites are guarded. A grep for `Method::PUT` in the crate returns exactly two hits, both
   preceded by the guard.
4. In `caldir-core`, `push_outgoing_changes` (`connection.rs:230`) detects, **before issuing any
   RPC**, that the outgoing set contains two items with the same `uid` and different
   `ComponentKind`, and returns a `ConnectionError` variant naming the UID. No RPC is sent for
   *any* change in that push once the condition holds.
5. The local mixed directory keeps working everywhere else: two identities, two base entries, two
   `known_event_ids` lines, no `doctor` duplicate warning (R100/A-6). `T-52`
   (`connection::tests::a_mixed_local_directory_keeps_both_items_distinct_end_to_end`, owned by
   `L4-03`) must still pass **unmodified**.
6. No href scheme is invented anywhere (R62): the href stays `{uid}.ics` for both kinds.

## Non-goals

- No merging, renaming, or auto-resolution of the pair — the error is the feature.
- No capability negotiation (ADR-07 is CUT; R73/R91).
- No second collection, no per-kind collection routing.

## Notes for the implementer

- **The provider can only produce a multi-component body by accident, and that is the point.**
  `CalendarItem::to_ics_string()` emits exactly one supported component per document (R27), so the
  guard should never fire in production. It exists because a `400`-answering server plus a retry
  path is an infinite loop (R80), and because R64 is INVIOLABLE — a structural guard is cheaper than
  a proof.
- **`T-52` interaction — RESOLVED, do not re-litigate.** `L4-03` owns `T-52`, which asserts a mixed
  local directory works end to end at the `Connection` seam. If its fixture pushed both same-UID
  items into one remote collection, this ticket's guard would fail it. **Ruling: the fixture moves,
  the guard does not weaken.** A-6/R100 requires *distinct identities and exactly one correct
  delete*, never a successful dual push, so `T-52` proves distinctness through two identities, two
  `bases/` files, two `known_event_ids` lines and one delete against the correct file — with the
  pair either never pushed in the same direction or split across two remotes. The dual-push-into-one
  -collection case is **this ticket's error path**, and its end-to-end proof is `T-56` on the live
  tier. The mirror of this note is in `L4-03.md` and in INDEX `L4-03`'s row; if you find a `T-52`
  that contradicts it, `T-52` is the thing that is wrong.
- Radicale's three rejection shapes are all in probe Q-E: `409` across hrefs (handled by `L5-03`),
  `400` within one resource (this ticket), silent `204` at the same href (the reason core must stop
  *before* the network — the server will not protect the user here).
- Trap: do not implement the guard by counting `BEGIN:` lines — `VALARM` is a nested component and
  caldir splices one in by hand on the literal `"END:VTODO\r\n"` (R24). Count only top-level
  data-bearing components, or reuse `L4-01`'s decoder and check its arity result.
- Trap: `just check` runs clippy with `-D warnings`; never run two cargo commands in parallel.
