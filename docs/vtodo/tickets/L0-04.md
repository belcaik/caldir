# L0-04: VTODO string fixtures for the whole feature

**PR-2** (the VTODO feature proper). PR-1 (`L0-01`/`L0-02`/`L0-03`) must have landed first.

## Responsibility
Add the inline `\r\n` ICS string constants that the L1–L5 tickets consume, to
`caldir-core/src/test_utils.rs`, next to the existing Stage-2 fixtures. **Strings only — no new
types, no helper that parses, no `test_todo()` builder.** That is why this ticket has no dependency
and can run in wave 0.

R19/R21/R22/R23/R32/R87/R101.

## Acceptance criteria
1. Every fixture in the table above exists as a `pub const &str` in `caldir-core/src/test_utils.rs`,
   with `\r\n` on every line including the last.
2. No new type, function, or trait is added; `write_ics` and the existing constants are unmodified.
3. Each constant carries a one-line comment naming the requirement/ticket it exists for (terse — see
   CLAUDE.md "Keep comments terse").
4. `just check` and `just test` green; the 686-test baseline unchanged. (R104)

## Non-goals
- **Do not** modify `VTODO_ICS`, `VEVENT_CONTROL_ICS`, or `EMPTY_VCALENDAR_ICS`. The five RED tests
  and their controls read them, and their assertion values are immutable (ADJUDICATION post-DAG
  ruling).
- **Do not** add a `test_todo()` structured builder or an `icalendar::Todo` factory — `L1-01`/`L1-03`
  own those, and adding them here creates a dependency this ticket exists to avoid.
- **Do not** add `CATEGORIES` fixtures. `CATEGORIES` is OUT (R88) and is a follow-up ADR for both
  kinds together.
- **Do not** create a `tests/` directory or any `.ics` file on disk. The workspace has none, by
  convention (testing.md §1, §4).

## Notes for the implementer
- **Probe hygiene (R108) applies if you verify a fixture with a scratch crate**: pin
  `icalendar = "=0.17.10"`, print the resolved version, and echo the exact input bytes you sent. Two
  probes in this effort produced wrong answers from unexamined inputs — one silently resolved
  0.17.13 behind a caret requirement, and one used bash `printf` and measured a fixture that carried
  no `COMPLETED` property at all. *A probe that returns the answer you expected is not evidence until
  you have inspected the input it actually sent.*
- Escape trap: in a Rust string literal `\r\n` is the two real bytes — correct. Do **not** write
  `\\r\\n`, and do not rely on a shell heredoc or `printf` to produce them.
- `test_utils.rs` is compiled only under `#[cfg(test)]` (`caldir-core/src/lib.rs:12`) and is
  **crate-private** — `caldir-cli` and the provider crates cannot use these constants. Tickets in
  those crates must inline their own strings; do not try to export this module.
- Constants nobody consumes yet may raise a `dead_code` warning under `cargo test`. `just check`
  (`cargo check --workspace` + clippy, no `--all-targets`) does not compile test code, so CI's
  `-D warnings` will not fail on it — but keep the set to exactly the table above so the window
  between this ticket and its consumers stays small.
- Keep every fixture minimally realistic: a `UID` and `DTSTAMP` on every component, `VERSION`/
  `PRODID` on every `VCALENDAR`, matching the u_crawler shape already in the file.
