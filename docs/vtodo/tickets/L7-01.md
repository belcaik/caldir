# L7-01 — agenda anchor + total order

## Responsibility

Introduce **one** function in `caldir-cli/src/output/agenda.rs`:

```
fn anchor(item: &CalendarItem) -> Option<&EventTime>
  Event(e) => Some(&e.start)
  Todo(t)  => t.due.as_ref().or(t.start.as_ref())
```

Every `entry.event.start` in the agenda sort becomes `anchor(&entry.item)`. `AgendaEntry.event: Event`
becomes `AgendaEntry.item: CalendarItem` (ADR-10 D1). Extend the sort chain with **exactly one** new
tiebreak at the end: kind ordinal, `Event(0) < Todo(1)` (ADR-10 D2). Undated items (`anchor == None`)
must be kept in the entry vector — suppression is L7-02's job — and sorted to the end of the vec.

## Requirements satisfied

- **R84** (placement/order): *"Tasks appear in the agenda anchored on `DUE` (falling back to `DTSTART`),
  interleaved with events in the existing day groups; for an event and a task at the same instant, event
  first. Undated tasks are never placed in a day group and never given an invented date."*
- **R85**: *"No existing sort behaviour may be made more deterministic here. A final identity tiebreak
  would improve event-vs-event ordering but would change existing text for existing situations, breaching
  C13. Own ticket."*
- **C13** (INVIOLABLE): *"Existing text for existing situations unchanged; an event-only calendar renders
  byte-identically."* For an `Event`, `anchor` returns `&e.start` — byte-identical to today, so event
  output is unchanged **by construction**.

## RED tests

**`T-46` — `caldir-cli/src/output/agenda.rs`, `mod tests`:**
`output::agenda::tests::event_task_and_all_day_on_one_day_order_correctly` **(TZ)**

Fixture: one calendar day carrying (a) an all-day event, (b) a task with a DATE-valued `DUE` on that day,
(c) an 09:00 event, (d) a 09:00 task. Assert the collected order is exactly: all-day event, date-DUE task,
09:00 event, 09:00 task. Asserts all four sort rules at once, including that rule 4 puts the event before
the task at an identical instant. Marked **TZ** because `local_date` is local-zone and a UTC-instant task
can land on a different local day in `America/New_York` than in `Europe/Stockholm`.

Add (not in the spec's T-table, but required to lock R85):
`output::agenda::tests::two_events_at_the_same_instant_keep_read_dir_order` — construct two events with
an identical `start`, assert the sort is *stable* (input order preserved). This is the guard that catches
an implementer who "helpfully" adds an `instance_id` tiebreak.

## Acceptance criteria

1. `anchor(&CalendarItem)` exists in `output/agenda.rs`, is the only place the "where does this item sit in
   time" question is answered, and returns `Some(&e.start)` for `Event` — no clone, no re-derivation.
2. For `Todo`, `anchor` is `due.or(start)`; `DUE` wins over the task's `DTSTART`.
3. `AgendaEntry` field is `item: CalendarItem`; the `event: Event` field is gone.
4. The sort chain is `local_date(anchor)` → `anchor.is_date()` reversed → `anchor.to_utc()` → kind ordinal.
   **Four** rules, in that order, in **both** copies (`agenda.rs` and `agenda_text.rs`).
5. No `instance_id`, `uid`, filename, or calendar-slug tiebreak is added anywhere.
6. Entries whose `anchor` is `None` are retained in `entries` and sorted last; they are not dropped and
   are not given a synthesized date.
7. `T-46` passes under `TZ=UTC`, `TZ=Europe/Stockholm`, `TZ=America/New_York`.
8. `cargo test -p caldir-cli` is green with **zero** edits to existing event tests (R104).

## Notes for the implementer

- **Trap — two sort chains.** `agenda.rs:51-62` and `agenda_text.rs:24-34` are duplicated today. Change
  both or `--json` and text disagree on order. The duplication is pre-existing; do not dedupe it here
  (that would be an unrelated refactor inside a C13-INVIOLABLE surface).
- **Trap — `sort_by` is stable.** That is load-bearing, not incidental: equal keys keep `read_dir` order.
  Do not switch to `sort_unstable_by`.
- **Trap — `Option` ordering.** Rust's `Ord for Option` sorts `None` *before* `Some`. If you sort on
  `anchor` directly, undated tasks land at the top of the agenda. Sort them explicitly to the end.
- `resolve_rsvp` (`agenda.rs:73-77`) takes `&Event`; narrow it (`let Some(e) = item.as_event() else { return None }`)
  rather than teaching it about tasks — a task has no invite semantics (R81, ADR-10 D7).
- `display_days` (`agenda_text.rs:72-90`) needs no change: a `Todo` has no `end`, so it always takes the
  `vec![local_date(..)]` fallback. Verify by reading, do not "improve" it.
- Toolchain is pinned to `1.97.0`; clippy runs with `-D warnings`.
