# L2-04 — migrate batch 2: `caldir-cli` call sites

**Layer:** L2 · **PR-2** · **Depends on:** `L2-02` · **Parallel with:** `L2-03`, `L2-05`

## Responsibility

The same mechanical migration for `caldir-cli`: re-point `CalendarEvent::event()` at
`item()` / `as_event()`. VEVENT-only consumers gain a narrowing
(`let Some(e) = ce.as_event() else { continue };`) rather than a rewrite.

**This ticket carries no R-number by design.** It exists so CI is green batch-to-batch and so
`L2-06` has nothing left to break (INDEX §4, *"Tickets covering no requirement"*).

## Scope — measured, not guessed

`grep -rn "\.event()" caldir-cli/src` on this branch finds **5 sites in 2 files**:

| File | sites | Shape |
|---|---|---|
| `caldir-cli/src/commands/rsvp.rs` | **4** | VEVENT-only by nature (RSVP on a task is meaningless, R81). Narrow with `as_event()`. |
| `caldir-cli/src/commands/doctor/warning/duplicate_file.rs` | **1** | `ce.event().event_instance_id()` at `:18`. Narrow, or move to `item()` — but **do not** implement kind-awareness here; that is `L2-08`. |

The INDEX row also names `output/agenda.rs`, `output/event.rs`, `commands/status.rs`,
`commands/discard.rs`. Grep shows those do **not** call `CalendarEvent::event()`: `agenda.rs`,
`agenda_text.rs` and `agenda_json.rs` read `.event` off the CLI's own `AgendaEntry` (an owned
`Event` from `Calendar::expanded_events_in_range`), and `output/event.rs` takes `&Event` directly
(`:1`, `:6`, `:12`). **Those files break at `L2-07`, not here.** Migrate whatever the compiler
actually breaks; the two files above are the authoritative starting point.

**You may split further and report back rather than rush** — the legacy accessor keeps each batch
green, so splitting is safe and expected (INDEX §6.3).

## Acceptance criteria

1. No `CalendarEvent::event()` call remains in `caldir-cli/src`.
2. Every narrowing is explicit; **no `unwrap()` on `as_event()`**, and no `filter_map` that
   silently discards an item without a comment naming the ticket that will handle it.
3. `git diff` shows **zero** changes to expected-output `indoc!` blocks in existing tests. (C13)
4. `just check` clean under `-D warnings`; `cargo test -p caldir-cli` green at 69; `just test`
   green at 686.

- **Do not** make `duplicate_file.rs` kind-aware — that is `L2-08`, and it depends on `L1-06`'s
  `ComponentKind` identity, which may not have landed yet.
- **Do not** implement R81's RSVP-on-a-task error message here — that is `L7-04`. Narrow only.
- **Do not** touch `doctor`'s `UnreadableEvents` behaviour (`doctor.rs:55-57`) — `L0-02`/`L7-05`.
- **Do not** delete the legacy `event()` accessor — `L2-06`.
- **Do not** touch `caldir-core` or the provider crates.

## Notes for the implementer

- `caldir-core/src/test_utils.rs` is `#[cfg(test)]` and **not exported** (`lib.rs:11-12`), so
  `caldir-cli` tests cannot use `VTODO_ICS` or `test_calendar()`. CLI tests build their own state
  locally — follow the existing pattern in `caldir-cli/src/commands/config.rs:39` and
  `calendars.rs:44`.
- `duplicate_file.rs:14-20` buckets by `EventInstanceId` into a `HashMap`. Once `L1-06` adds
  `ComponentKind` to that key, hazard 5 closes on its own; your job here is only that the file
  compiles against the new accessor.
- CI runs the CLI suite under all three timezones (`UTC`, `Europe/Stockholm`,
  `America/New_York`). A pure accessor rename is TZ-neutral; a TZ failure means you changed
  behaviour.
- `-D warnings` is on in CI's `check` job via `RUSTFLAGS`; an unused import left behind by a
  narrowing will fail the build.
