# L2-07 — `Calendar::events()` / `expanded_events_in_range` list tasks ⚑ *the green moment, levels 2+3*

**Layer:** L2 · **PR-2** · **Depends on:** `L2-06`, `L0-01`

## Responsibility

Tasks flow through the calendar listing and into range expansion. A recurring task's `RRULE` is
**modelled, never expanded** (master only); an undated task is **never given an invented date**.
The last two of the five immutable Stage-2 RED tests go green here.

  cross-contamination at either the core or the CLI level."

  Supported, non-error local state."
- **R5 (levels 2 and 3, fully)** — "A file containing exactly one VTODO MUST load, MUST NOT error,
  and MUST NOT prevent any sibling file, sibling calendar, or CLI aggregation from loading."

- **R46 (INVIOLABLE, in force here)** — "No synthesized dates. An undated task MUST NOT be given a
  fabricated date." Range expansion is exactly where an implementer is tempted to invent one.

## Acceptance criteria

1. `Calendar::events()` returns tasks alongside events, preserving `L0-01`'s incomplete-listing
   signal. (R5 level 2, R78)
2. `T-3` passes with its assertion line unmodified. (R5 level 2)
3. `expanded_events_in_range` yields tasks; `T-4` passes with its assertion unmodified.
   (R5 level 3)
4. A recurring task (has `RRULE`) yields **exactly one** item from range expansion — the master.
   No occurrence expansion. (R89)
5. An undated task is never assigned a date by the expansion path; `grep` the diff for any
   `unwrap_or`/`unwrap_or_else` supplying a fabricated `EventTime`. (R46)
6. `Calendar::event(slug)` and `event_by_instance_id` resolve a task file. (R3, R4)
7. A directory holding a same-UID VEVENT + VTODO pair lists **two** items, no error. (R4, R100)
8. `just test` green at 686 + new tests, **zero edits to existing event tests** (R104), in all
   three CI timezones.

## Non-goals

- **Do not** decide whether a task is *in the sync window*. The four-row R44 predicate is
  `L3-02`, ships in **one commit** with R51/R58, and splitting it reproduces the data-loss bug
  §10 traces. Listing ≠ window membership.
- **Do not** render anything. Agenda anchoring and ordering is `L7-01`; task text and the undated
  footer is `L7-02`; `--json` is `L7-03`.
- **Do not** change `Event::occurs_in_range` (`caldir-core/src/event.rs:136-141`) — **R45**
  requires it unchanged byte for byte.
- **Do not** touch `expand_in_range`/`expand_master` (`event/occurrences.rs:110-130`) for events.
- **Do not** re-open the poison-pill `?` design. `L0-01` settled it (Q-6, the listing struct).
