# L1-02: shared equality helpers, referenced by both types

**PR-2.** ⚠ **HIGH RISK — read this section before touching anything.**

This ticket moves `x_properties_eq` and `attachments_eq` out of `caldir-core/src/event.rs`, which
means it **touches `Event`'s `PartialEq`**. `==` on the domain item is the sync engine's only
"content changed?" test (R12). A slip here does not produce a compile error or a red test in the new
code — it silently changes **sync direction for every existing user**, in a way the user only
discovers as lost edits.

- **R2 (INVIOLABLE)** — *"VEVENT behaviour MUST NOT change observably: same bytes, filenames, parse result, equality, sync direction, text output."*
- **C2 (INVIOLABLE)** — *"An existing VEVENT file parses to a structurally `==` event before and after; event equality unchanged."*
- The unmodified **686-test baseline is the only guard**. If any existing test needs an edit to pass,
  that is a design failure, not a fixup (R104). Stop and report.

## Responsibility
Move the two comparison helpers into a `pub(crate)` module and point **both** `Event`'s and `Todo`'s
`educe` attributes at the same functions, so drift on those fields is structurally impossible. Then
write `Todo`'s `PartialEq`.

## Requirements satisfied
- **R12** — *"`==` on the domain item is the sync engine's only "content changed?" test. A field that cannot survive `serialize -> parse` losslessly MUST NOT participate in `==`, or it generates permanent churn."*
- **R38** — *"Task equality MUST mirror event equality exactly: `last_modified`, `sequence` and `created` ignored; `x_properties` compared order-independently by name+value with parameters ignored; attachments by URI only. The two comparison helpers MUST be moved to a shared location and referenced by **both** types, making drift on those fields structurally impossible."*
- **R39** — *"`status`, `completed`, `percent_complete`, `due`, `start`, `priority`, `summary`, `description` and all other content fields MUST participate in `==`. Ignoring any of the first three would mean "task completed" never syncs — the worst possible silent failure for VTODO."*

## RED tests
- **ADD** `todo::tests::equality_mirrors_event_equality` (**T-18**, spec §18, R38/R39) in
  `caldir-core/src/todo.rs`'s test module. Per spec §18 it MUST assert all four behaviours:
  1. same `last_modified` / **different `sequence`** ⇒ equal (and `created` differing ⇒ equal);
  2. reordered `x_properties` ⇒ equal;
  3. reordered `attachments` ⇒ equal;
  4. a change to `status`, `completed`, or `percent_complete` ⇒ **unequal**.
  Why: (1)-(3) are the ignore/order rules that, if wrong, cause permanent push churn; (4) is the one
  R39 singles out — if `status`/`completed` were ignored, "task completed" would never sync, the
  worst possible silent failure for VTODO.
- **KEEP GREEN, UNEDITED**: every existing equality test in `caldir-core/src/event.rs` and every
  direction test in `caldir-core/src/diff/calendar_diff.rs` and `caldir-core/src/connection.rs`.
  These are the R2/C2 guard.

## Acceptance criteria
1. `x_properties_eq` and `attachments_eq` live in `caldir-core/src/event/equality.rs`, are
   `pub(crate)`, and their **bodies and comments are moved verbatim** — no logic edit. (R38)
2. `Event`'s `educe` attributes reference the moved functions; the set of ignored fields
   (`last_modified`, `sequence`) and the set of method-compared fields (`attachments`,
   `x_properties`) is unchanged. (R2, C2)
3. `Todo` derives `PartialEq` through the **same** functions, ignoring `last_modified`, `sequence`
   and `created`, and comparing every content field including `status`, `completed`,
   `percent_complete`, `due`, `start`, `priority`, `summary`, `description`. (R38, R39)
4. `todo::tests::equality_mirrors_event_equality` passes. (T-18)
5. `just test` shows the **686-test baseline green and unmodified** — zero edits to existing event
   tests. This is criterion 5 for a reason: it is the only evidence that R2/C2 held. (R104)

## Non-goals
- **Do not change what either helper does.** Not the `XProperty` params-ignoring `PartialEq`, not
  "attachments compared by URI only". Both look like bugs and are deliberate, documented decisions
  (`event.rs:281-292`, `x_property.rs:10-16`). "Fixing" either one changes event sync direction.
- **Do not** add or remove a field from `Event`, reorder its fields, or change its derive list beyond
  repointing the two method paths.
- **Do not** implement `Hash`, `Ord`, or a "semantic equality" variant for either type.
- **Do not** decide Q-4 (`percent_complete: None` vs `Some(0)`) — it is open, and a wrong guess here
  is a permanent A-2 idempotence failure.
- No codec, no slug, no identity work — `L1-03`/`L1-04`/`L1-06`/`L1-07`.

## Notes for the implementer
- Do the move as a **pure move first**: cut both fns into the new module, repoint `Event`, run
  `just test`, confirm 686 green. Only then add `Todo`'s `PartialEq`. Two commits, or at minimum two
  verified checkpoints — so that if the baseline breaks you know which half did it.
- `educe`'s `method(...)` attribute takes a function name resolvable in scope. If a fully-qualified
  path does not compile, add a `use crate::event::equality::{attachments_eq, x_properties_eq};` in
  each file rather than duplicating the function — duplication is precisely what R38 forbids.
- `Event` derives `Eq` as well as `PartialEq`; keep that, and give `Todo` the same treatment only if
  every one of its fields is `Eq`.
- `created` is ignored by `==` but IS a field (ADJUDICATION C-4: it exists on data-safety grounds to
  rescue an undated completed task from RFC 4791 §9.9 omission). Ignoring it in `==` is required;
  deleting the field is not.
- Conventions: inline `#[cfg(test)] mod tests`, no fixture files,
  `use pretty_assertions::assert_eq;`.
- CI: `just check` with `RUSTFLAGS: -D warnings`; `just test` across `TZ` = `UTC`,
  `Europe/Stockholm`, `America/New_York`.
