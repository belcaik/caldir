# L4-04 — A-2 idempotence gate at the `Connection` seam

> Layer L4 · PR-2. Tests only, in `caldir-core/src/connection.rs`'s test module.
> **The load-bearing gate of the whole effort** — it catches every churn mechanism at once,
> including ones nobody enumerated.

## Responsibility

Sync twice against the mocked transport; assert the **second diff is empty**. The comparison is
**parsed-domain `==`** — never raw bytes.

## Requirements satisfied

- **R96 (A-2).** *"Syncing twice against the same remote MUST produce an **empty diff** on the
  second run. This is the load-bearing gate: it catches every churn mechanism at once, including
  ones not enumerated. The comparison MUST be parsed-domain `==` or GET-pass-2 vs GET-pass-1
  (R30)."*
- **R30 (INVIOLABLE for acceptance gates), at the C tier.** *"No gate may compare **raw bytes**
  of what caldir PUT against what the server GETs back. Radicale does **not** echo
  byte-for-byte (probe Q-C): properties re-sorted alphabetically within each component, lines
  re-folded at 75 octets, `VTIMEZONE` synthesized for any `TZID`. It **is** idempotent — the
  second round trip is byte-identical. Gates MUST compare **parsed domain `==`**, or GET-pass-2
  against GET-pass-1."*
- Adjacent and binding: **R31.** *"ETag MUST NOT be used to prove 'caldir's push was a no-op':
  … caldir re-stamps `DTSTAMP` on every serialize (R25), so **every caldir push mutates the
  ETag even when nothing changed**. It MAY prove 'the remote changed'."*
- `ADJUDICATION.md` § "ADR-06 amendment — acceptance gate must be STRUCTURAL" says the same,
  and is **BINDING**.

## Dependencies

`L4-03` (items flow end to end), `L3-04` (the R49 belt — otherwise a task-less second response
would mask churn behind a suppression).

## RED tests

**`T-49`** — `connection::tests::syncing_twice_against_a_fake_remote_yields_an_empty_second_diff`
in `caldir-core/src/connection.rs`. Layer **C**, **TZ-marked (R106)**.

Shape: build a writable connection over a temp calendar holding at least one **task** (ideally
the u_crawler-shaped fixture: `UID`, `DUE`, `SUMMARY`, `DESCRIPTION`, `URL`, `PRIORITY`,
`STATUS:COMPLETED`, `COMPLETED`) and one control **event**. Run `diff` → apply → `diff` again
with the mock replying with the items the first run pushed. Assert `second_diff.is_empty()`.

Two assertions matter and both must be present:

1. `assert!(second.is_empty())` — the gate itself.
2. On failure, print the offending changes (`incoming()` / `outgoing()`) so the ADR-06 table can
   be consulted. *Why:* a bare boolean failure here is nearly undebuggable; the diagnostic is
   part of the test's value.

**How the mock's second response must be built:** re-serialize the items caldir wrote and feed
them back through the same parse path — i.e. compare **domain values**, not text. Do **not**
hand the mock a hand-written ICS string that happens to differ in property order, and do **not**
assert on strings anywhere in this test.

## Acceptance criteria

1. `T-49` exists with exactly that name and passes.
2. It passes under `TZ=UTC`, `TZ=Europe/Stockholm` **and** `TZ=America/New_York`.
3. The fixture includes at least one **task** and one **event**; an event-only version of this
   test proves nothing about VTODO.
4. The only equality used is parsed-domain `==` / `CalendarDiff::is_empty()`. No
   `assert_eq!` on ICS text, no byte comparison of a file against a payload, no ETag assertion
   (R30, R31).
5. The test exercises the real `Connection::diff` path including `bases_to_backfill` — do not
   pre-seed bases by hand in a way that skips the migration this gate is meant to cover.
6. No production code changes are needed to make it pass. **If it goes red, the bug is in an
   earlier ticket** — fix it there, do not relax this test.
7. `SUITE` green with zero edits to existing event tests (R104).

## Notes for the implementer

- **Trap — the forbidden-but-obvious assertion.** Comparing what caldir wrote against what came
  back, as text, is the natural way to write this and is banned by R30: Radicale sorts
  properties alphabetically, re-folds lines at 75 octets, and synthesizes `VTIMEZONE`. A
  byte-comparing gate is permanently red against a real server and gives false confidence
  against a mock that happens to echo.
- **Trap — ETag looks like the perfect proof and is not** (R31): caldir re-stamps `DTSTAMP` on
  every serialize (R25), so **every** push mutates the ETag even when nothing changed. ETag can
  prove "the remote changed"; it can never prove "the push was a no-op".
- **Trap — a mock queue that runs dry mid-test panics** (`mock_transport.rs:82`). Two syncs mean
  two `ListEvents` replies plus one reply per applied change, in FIFO order.
- **Trap — an accidentally empty first diff makes this test vacuous.** Assert the *first* diff is
  non-empty before applying it; otherwise "the second diff is empty" is true for free.
- If it fails, walk ADR-06's nine mechanisms in order: DTSTAMP-as-content, lossy
  `COMPLETED`/`PERCENT-COMPLETE`/`STATUS`, floating `COMPLETED`, unknown `STATUS`, VALARM UID
  regeneration, `DTEND` leakage via `EventLike`, stripped provider `X-*` props.
