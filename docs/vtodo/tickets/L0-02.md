# L0-02: CLI + doctor consume the listing without changing a byte of text

**PR-1.** Ships in the first PR together with `L0-01` and `L0-03`. R6 requires the degradation
change to include R48 (`L0-03`); a degrading core without the C7 guard, paired with a VTODO-aware
provider, deletes the user's tasks server-side.

**PR-1 turns NONE of the five VTODO RED tests green.** They assert the VTODO *loads and is visible*.
This ticket's exit criterion is its own tests plus the unmodified 686-test baseline.

## Responsibility
Teach the two CLI consumers of `Calendar::events()` to handle the new listing: `AgendaView::collect`
stops aborting the whole cross-calendar aggregation when one calendar fails, and `doctor` keeps
reporting a syntactically broken VEVENT as `DoctorWarning::UnreadableEvents` now that a bad file no
longer makes `events()` return `Err`. **No existing text output or exit code may change.**

## Requirements satisfied
- **R5** (level 3) — *"A file containing exactly one VTODO MUST load, MUST NOT error, and MUST NOT prevent any sibling file, sibling calendar, or CLI aggregation from loading."*
- **R77** — *"A syntactically broken **VEVENT** MUST still surface as `DoctorWarning::UnreadableEvents` (`doctor.rs:55-57`). Graceful degradation MUST NOT start silently swallowing malformed files (§15 C13)."*
- **C13** (INVIOLABLE) — *"Existing text for existing situations unchanged; an event-only calendar renders byte-identically; `doctor` still reports a broken VEVENT as `UnreadableEvents`."*

- **ADD** `commands::doctor::tests::a_malformed_vevent_is_still_a_warning_after_component_skipping`
  (**T-43**, spec §18) in `caldir-cli/src/commands/doctor.rs`. It writes a syntactically broken

  more-deterministic sort changes existing text and is its own ticket. The sort chain at

  or `rsvp`/`invites` narrowing (`L7-04`).
- **Do not** re-lock T-43 against the item-backed loader — that is `L7-05`, after `L2-07`.

## Notes for the implementer
- **`test_caldir()` is unavailable here.** `caldir-core/src/test_utils.rs` is `#[cfg(test)] mod`
  and not exported (`lib.rs:12`), so `caldir-cli` cannot use it. Copy the local pattern already in
  `doctor.rs:66-71`: `tempfile::tempdir()` + `Calendar::create(&tmp.path().join("work"), None)`.
- The existing `doctor` test writes `"BEGIN:VCALENDAR\nVERSION:2.0\nEND:VCALENDAR"` — a
  *component-less* document, which is a different case from a *malformed* one. Your T-43 fixture
  must be a genuinely broken VEVENT so it exercises R77 rather than the empty-document path that
  `doctor.rs:75-91` already depends on (R75).
- `AgendaView::collect` calls `calendar.expanded_events_in_range(...)`, not `events()` directly
  (`agenda.rs:35` → `caldir-core/src/calendar.rs:328-335`). After `L0-01` that call only fails for
  directory-level errors — but R5 level 3 requires the aggregation to survive **any** single
  calendar's failure, so handle the `Err` arm here rather than assuming it cannot fire.
- Skipping a calendar must not reorder or otherwise perturb the entries of the calendars that did
  load; entry order is C13-protected text.
- CI: `just check` runs with `RUSTFLAGS: -D warnings`; `just test` runs under `TZ` = `UTC`,
  `Europe/Stockholm`, `America/New_York`.
