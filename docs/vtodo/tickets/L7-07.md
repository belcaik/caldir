# L7-07 — the diff renderer carries items (`status` / `pull` / `push` / `sync` / `discard`)

## Responsibility

`caldir-cli/src/output/diff.rs` renders every `EventChange` the user ever sees before a sync. Once
`EventChange` carries a `CalendarItem` (`L3-03`), this file has **two** problems, and only the
first one is loud:

1. **It does not compile.** `diff.rs:45` is
   `format_datetime(&event.start, caldir.config().time_format())`. `Event::start` is an
   `EventTime`, not an `Option`, and a `Todo` has no `start` in that shape at all.
2. **Past the compile error it is silently wrong.** `render_field_diffs` (`:221-275+`) compares
   `summary`, `description`, `location`, `start`, `end`, `status`, `recurrence`, `recurrence_id`,
   `reminders` — **every one an `Event` field**. Change only a task's `DUE` or its task status and
   the renderer emits **nothing**: the user is shown an empty diff while a real change is pushed.

Fix both. Route the one-line render through `anchor(item)` (owned by `L7-01`), printing `(no date)`
where the anchor is `None`, and give `render_field_diffs` a `due` row and a task-status row.

## Requirements satisfied

- **R84** — the diff surface's half of task display. ADR-10 §D7's
  `status`/`pull`/`push`/`sync`/`discard` row is marked **MVP (compile-forced; two rows are the
  minimum)**.
- **C13** (INVIOLABLE) for the untouched path: an event-only diff renders byte-identically.

## Tests

**New — `caldir-cli/src/output/diff.rs`, `mod tests`:**

`output::diff::tests::a_task_only_update_renders_a_non_empty_field_diff`

Build an `EventChange::Update { from, to }` over **two tasks** differing in exactly one field, and
assert the rendered field-diff is non-empty and names that field. Run it twice: once with `due`
changed, once with the task status changed (`NEEDS-ACTION` → `COMPLETED`). This is the test that
would have caught the hole; assert `!lines.is_empty()` **before** asserting on content, so the
failure message says "empty diff" rather than "expected `due` in ``".

`output::diff::tests::an_event_only_diff_renders_byte_identically` **(C13 lock)**

A fixture of event-only `Create` / `Update` / `Delete` changes; assert the rendered string is
byte-identical to the pre-change output, including colour escapes, the `🔁` recurring marker and
the `(Untitled)` fallback. Capture the expected string from `main` before starting.

## Acceptance criteria

1. `impl Render for EventChange` uses `anchor(item)` — imported from `L7-01`, not redefined — and
   renders `(no date)` when it is `None`.
2. `render_field_diffs` gains a `due` row and a task-status row. Two rows is the stated minimum;
   do not attempt a full per-field parity sweep for `Todo` in this ticket.
3. An `Update` whose two sides are **different kinds** is impossible by construction (identity is
   kind-carrying after `L1-06`), but it must not panic if one is constructed in a test — render a
   plain summary line rather than `unwrap`.
4. Event-only diffs are byte-identical: same colours, same symbols, same ordering, same
   `(Untitled)` fallback (C13).
5. The task status is rendered with the **existing colour roles only** — no new palette entry,
   matching `L7-02`'s constraint.
6. `cargo test -p caldir-cli -- output::diff` green; `just test` green; **zero edits to existing
   event tests** (R104).

## Non-goals

- The agenda renderer and `format_task_line` — `L7-02`.
- `anchor` itself and the sort order — `L7-01`.
- The `--json` schema — `L7-03`. The diff surface has no JSON form.
- A per-field diff for every `Todo` property. ADR-10 says two rows are the minimum and the MVP;

- Retyping `EventChange` — that is `L3-03`'s, in core.

## Notes for the implementer

- **Trap — the empty diff is the bug, not the compile error.** It is tempting to make `diff.rs`
  compile with a `let Some(event) = item.as_event() else { return String::new() };` and move on.
  That produces exactly the failure ADR-10 warns about: a task edit renders as nothing, in the
  command whose entire purpose is to show the user what is about to be pushed. The narrowing idiom
  is correct in `rsvp`/`invites` (`L7-04`), where skipping is the specified behaviour, and wrong
  here.
- **Trap — `(no date)` vs an empty column.** Undated tasks are *counted, not listed* in the agenda
  (`L7-02`), but the diff has no footer to count into: a task with no `DUE` that is about to be
  created must still render as a line. Print `(no date)`, do not skip.
- **Trap — the C13 baseline.** Capture the event-only expected output from `main` before you start
  editing. Reconstructing it afterwards from your own implementation proves nothing.
- `EventChange` is `#[allow(clippy::large_enum_variant)]` today; a `CalendarItem` payload will not
  shrink it. Leave the attribute.
- Toolchain `1.97.0`; clippy `-D warnings`; CLI tests use `indoc`; never run two cargo commands in
  parallel.
