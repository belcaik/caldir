# L8-06 — record what is deferred, not implemented

## Responsibility

Write the non-goals and open questions into `docs/vtodo/BACKLOG.md` so nothing that was deliberately not
built is lost. **Record only. Implement nothing.**

## Requirements satisfied

- **R92 (record for follow-up, do not implement)** — verbatim: *"`supported-calendar-component-set` **is**
  advertised by Radicale on every calendar collection at Depth 0 and Depth 1 (default `VTODO,VEVENT,
  VJOURNAL`; a VTODO-only collection returns `VTODO`), absent (404) on the principal, and **bulk-readable
  via ONE Depth-1 PROPFIND on the home-set** — so per-calendar round trips are unnecessary. But it is
  **ADVISORY ONLY**: a VEVENT PUT into a VTODO-only collection returned `201` (probe Q-A). **It can
  therefore never be an enforcement point**, and any future work MUST treat the declared value as a hint
  that can simply be wrong."*
- **R94**: renaming the `Event*`-prefixed shared types — deferred, ~20 call sites of churn for zero
  behavioural benefit.
- **R108 (probe hygiene, project rule)**: *"Any future probe crate MUST pin `icalendar = "=0.17.10"`, MUST
  print the resolved version, and MUST echo the exact input bytes it sent."*
- **R69** *(records the gap)*: every statement in spec §12 is **UNVERIFIED for iCloud (Apple Reminders)** —
  whether it 409s a same-UID pair (load-bearing for R62/R65), implements RFC 4791 §9.9 (R58), or injects
  non-`X-` properties (R67), and whether Reminders collections are returned by discovery at all.

## Acceptance criteria

`BACKLOG.md` contains, each as its own entry with enough context to act on years later:

1. **The probe-hygiene project rule (R108)** — pin `icalendar = "=0.17.10"`, print the resolved version,
   echo the exact input bytes sent. Include C-3's two worked failures as the justification, and the closing
   line: *"A probe that returns the answer you expected is not evidence until you have inspected the input
   it actually sent."*
2. **`supported-calendar-component-set` (R92)** — recorded with **all** of: it is advertised by Radicale on
   every collection at Depth 0 and Depth 1; the default value is `VTODO,VEVENT,VJOURNAL` and a VTODO-only
   collection returns `VTODO`; it is 404 on the principal; it is bulk-readable via **ONE Depth-1 PROPFIND**
   on the home-set, so per-calendar round trips are unnecessary; and — stated as the headline, not a
   footnote — **it is ADVISORY ONLY and can NEVER be an enforcement point**, because a VEVENT PUT into a
   VTODO-only collection returned `201` (probe Q-A). Any future work must treat the declared value as a hint
   that can simply be wrong. **Record; do not implement.**
3. **The unmeasured iCloud behaviours (R69)** — the three load-bearing unknowns (same-UID 409 → R62/R65;
   §9.9 → R58; non-`X-` property injection → R67) plus whether Reminders collections appear in discovery at
   all. Settled by: running the same six probes against a real iCloud account. *Nothing else will do it.*
4. **The deferred `Event*` rename (R94)** — cosmetic, ~20 call sites, deferred unless a maintainer asks.
5. **Q-1 through Q-11**, each with its question **and** its *"Settled by:"* clause. Q-2 is a special case:
   if `L8-01` settled it (the `specs/caldir.md` §To-dos terminology), record it as **settled and how**,
   rather than deleting it. Same for Q-3 if `L5-05` settled it.
6. Nothing in `BACKLOG.md` is phrased as a task to do *now*; every entry is explicitly deferred, with its
   trigger condition.

## Notes for the implementer

- **Trap — implementing R92.** The evidence in it reads like a design ("one PROPFIND gets everything!").
  That is exactly why it is dangerous: the mechanism works and the *semantics* do not. A `201` on a
  forbidden PUT means enforcement built on this property would reject valid operations and permit invalid
  ones. Write the caveat first, in the entry's first sentence.
- **Trap — summarising Q-1..Q-11 into a list of titles.** The *"Settled by:"* clauses are what make them
  actionable later. Carry them across.
- **Trap — deleting a settled question.** Record the resolution and who settled it. A backlog that silently
  loses questions cannot be audited.
- This ticket touches no Rust. Run `cargo test` once to confirm a clean tree.
