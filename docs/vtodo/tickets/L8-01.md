# L8-01 — amend `specs/caldir.md`

## Responsibility

Amend the canonical ICS-format spec so it describes tasks. Five edits, no more. **No existing VEVENT
sentence may change** (R2/C2). This ticket also settles Q-2's terminology dependency for `L7-03`, so it
must land **before** `L7-03`.

## Requirements satisfied

- **R16** (verbatim): *"`specs/caldir.md` MUST be amended in the same change: scope `PRIORITY` to 'skipped
  on VEVENT, used on VTODO'; add a `RELATED-TO` row to 'Fields We Skip'; drop the stale `RDATE` row (RDATE
  **is** implemented, `event/recurrence.rs:5-17`); add a `## VTODO (Task)` section covering the IN set plus
  *'VTODO uses DUE, never DTEND (RFC-invalid) and never DURATION'*; add a Tasks subsection to §'Filename
  Convention'. No existing VEVENT sentence may change (R2)."*
- **R15** — the user guarantee, to be reproduced **verbatim**: *"caldir round-trips a task's modelled
  properties plus every `X-` property verbatim, parameters included; any other property — `CATEGORIES`,
  `GEO`, `RELATED-TO`, `RESOURCES`, `COMMENT`, `CONTACT`, and any other IANA or vendor property caldir does
  not model — is dropped the first time caldir writes that item, on disk and on the server alike, exactly as
  it already is for events."*
- **R88** (doc half): `CATEGORIES` stays OUT for both kinds; a todo-only exception inside a table titled
  "Fields We Skip" is incoherent.

## Acceptance criteria

1. The `PRIORITY` row is **narrowed**, not deleted: it now reads as "skipped on VEVENT, used on VTODO"
   (or equivalent). VEVENT behaviour is unchanged.
2. A `RELATED-TO` row is **added** to "Fields We Skip", citing the parser collapse (R87: the `MULTIS` list
   carries the ABNF placeholder `"RELATED"`, so two lines in yield one out with `PARENT` gone).
3. The `RDATE` row is **removed** — RDATE is implemented (`event/recurrence.rs:5-17`). This is one of the
   ADJUDICATION's carried-forward doc corrections.
4. A new `## VTODO (Task)` section exists, covering the R13 IN set, and containing the sentence
   **"VTODO uses DUE, never DTEND (RFC-invalid) and never DURATION"**.
5. That section names the task status vocabulary (`NEEDS-ACTION` / `IN-PROCESS` / `COMPLETED` / `CANCELLED`)
   and **states the term caldir uses for it**. `L7-03` reads this to settle Q-2 — write it deliberately.
6. §"Filename Convention" gains a **Tasks** subsection documenting the `_task__` reserved prefix in all
   three shapes (recurring / dated / undated) with real examples matching `caldir-core/src/todo/slugify.rs`.
7. R15's guarantee appears verbatim in the document.
8. `git diff specs/caldir.md` shows **no** modified line inside the `## VEVENT (Event)` section and no
   changed wording in any pre-existing VEVENT sentence. The `PRIORITY` row narrowing and the `RDATE`
   deletion are the only edits to pre-existing lines.
9. `CATEGORIES`, `GEO`, `RESOURCES`, `COMMENT`, `CONTACT`, `CREATED` rows stay as they are **except** where
   the adjudication says otherwise. Do **not** over-widen this edit.

## Notes for the implementer

- **Trap — CREATED.** The existing row says CREATED is skipped. C-4 flipped it **IN for VTODO** on
  data-safety grounds (it is what rescues an undated completed task from RFC 4791 §9.9 omission). Handle it
  the same way as `PRIORITY`: scope the row, do not delete it, and do not silently change VEVENT behaviour.
- **Trap — over-widening.** R16 lists exactly five edits. Every additional "while I'm here" improvement is a
  chance to breach R2 on a VEVENT sentence. Resist.
- **Trap — writing the IN set from memory.** Use `docs/vtodo/spec.md` §6 R13's table. It differs from
  ADR-04's original in seven properties (C-2's FLIP IN list) and from RFC 5545's full VTODO surface in many.
- Q-2 (`task_status` vs `todo_status`) is downstream of criterion 5. Pick one, and pick it because of what
  reads best in this document — that is exactly the basis the spec deferred it to.
