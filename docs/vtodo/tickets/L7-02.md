# L7-02 — task text rendering, the undated footer, and `--undated`

## Responsibility

Add `format_task_line` as a **sibling** of `format_event_line` (ADR-10 D4), thread a new `undated: bool`
through `AgendaView::collect` and the three commands that feed it, count-not-list undated tasks in a single
dimmed footer by default, and render them under a trailing `No date` section when `--undated` is passed.
An event-only calendar must render **byte-identically** to today.

## Requirements satisfied

- **R84** (rendering half): tasks interleave in the existing day groups; *"Undated tasks are never placed
  in a day group and never given an invented date."*
- **C13 (INVIOLABLE)**: *"Existing text for existing situations unchanged; an event-only calendar renders
  byte-identically; `doctor` still reports a broken VEVENT as `UnreadableEvents`."*

## Acceptance criteria

1. `format_task_line` produces `"  {time:>7} {box} {summary} {[cal].dimmed()}"` — 2-space indent, the same
   7-wide right-aligned time column as `format_event_line`, no new indent level.
2. `{box}` is ASCII: `[ ]` NEEDS-ACTION, `[~]` IN-PROCESS, `[x]` COMPLETED. No emoji.
3. `{time}` is the clock time when `DUE` carries one; the literal `due` right-padded to 7 when `DUE` is a
   DATE (**never** the string `all-day` for a task); 7 spaces when the task is undated.
4. Colour uses existing roles only: COMPLETED ⇒ summary `.dimmed()`; `DUE` in the past and not COMPLETED ⇒
   summary `.red()`. Nothing else is coloured. No new colour role is introduced.
5. `is_visible` extends to `CalendarItem`: `Todo ⇒ status != TodoStatus::Cancelled`; the `Event` arm is
   unchanged. **COMPLETED tasks are shown by default** — see the trap below.
6. Default text output lists no undated task and ends with exactly one dimmed footer line when ≥1 exists;
   the footer is absent when none exist (an event-only calendar must not gain a trailing blank line).
7. `--undated` exists on `events`, `today`, and `week`, threads a `bool` into `AgendaView::collect`, and
   renders a trailing section headed `No date` with the same `.bold()` as a day label.
8. `--undated` changes **text only**. `--json` always emits the full set (ADR-10 D3; Q-1 recorded as open).
9. `T-45` passes under all three TZs; `cargo test -p caldir-cli` green; **zero** edits to existing event
   tests (R104).

## Non-goals

- `--hide-completed`, or any config key for it (ADR-10 D5: explicitly deferred).
- A per-day "Tasks" sub-group (ADR-10 option B, rejected).
- Any `--json` schema change (L7-03).
- `caldir tasks` as a standalone command (ADR-10 option C, overruled).

## Notes for the implementer

- **Trap — hiding completed tasks.** Do not. The MVP's own fixture is `STATUS:COMPLETED` (u_crawler);
  hide-by-default hides the demo case and is a silent drop, the exact class the whole spec rules against.
  ADR-10 D5 states the four reasons. If you feel the urge, read D5 before writing code.
- **Trap — the `all-day` string.** `format_time_only` prints `all-day` for `EventTime::Date`. A date-valued
  `DUE` is **not** all-day; it prints `due`. Reusing `format_time_only` unchanged for tasks is the easy
  wrong answer.
- **Trap — CLI text tests.** Use `indoc!` (see `commands/calendars.rs:24-50`). `owo_colors` emits ANSI
  escapes; the existing tests handle this — follow whatever they do rather than inventing a stripper.
- **⚠ DAG GAP — `caldir-cli/src/output/diff.rs` is assigned to no ticket in INDEX.md.** It is a
  *compile-forced* ripple with a silent-failure mode, so it must not be lost:
  - `diff.rs:45` `format_datetime(&event.start, …)` **will not compile** for a todo once `EventChange`
    carries a `CalendarItem`. Use `anchor`; print `(no date)` on `None`.
  - `render_field_diffs` (`diff.rs:220-275`) compares `summary`/`description`/`location`/`start`/`end`/
    `status`/`recurrence`. It **must** gain `due` and task-status rows. Without them, **editing only a task
    renders an empty diff** in `status` / `pull` / `push` — a silent-nothing bug, not a cosmetic gap.
  If `L2-04` did not already handle `diff.rs`, do it here and say so in the PR description; either way,
  raise the gap with the maintainer rather than leaving it to `L8-05` to discover.
- Toolchain `1.97.0`; clippy `-D warnings`; never run two cargo commands in parallel (rustup race).
