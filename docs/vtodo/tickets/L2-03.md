# L2-03 — migrate batch 1: `caldir-core` call sites

**Layer:** L2 · **PR-2** · **Depends on:** `L2-02` · **Parallel with:** `L2-04`, `L2-05`

## Responsibility

Mechanically re-point `caldir-core`'s `CalendarEvent::event()` call sites at `item()` /
`as_event()`. **Behaviour-preserving.** CI stays green throughout because `L2-02`'s legacy
`event()` accessor still exists — you are removing dependence on it, not removing it.

**This ticket carries no R-number by design.** It exists so that CI is green batch-to-batch and
so that `L2-06` (the contract flip) has nothing left to break. The R-value lives in
`L2-01`/`L2-02`/`L2-06`. See INDEX §4 *"Tickets covering no requirement"*.

## Requirements satisfied

None. Mechanical migration. The negative constraint that *does* bind: **R2 (INVIOLABLE)** —
"VEVENT behaviour MUST NOT change observably: same bytes, filenames, parse results, sync
direction" — and **C2**. `just test` (686 baseline) is the only thing standing between a
mechanical rename and a silent change to sync direction for every existing user.

## RED tests

None new. **`just test` (686 tests, unmodified) is the gate.** A migration that needs an existing
event test edited is a design failure, not a fixup (R104, A-10).

## Acceptance criteria

1. No `.event()` call remains in `diff/calendar_diff.rs`, `calendar.rs`, or `connection.rs`.
2. Every migrated site reads an `Event` through `as_event()` with an explicit narrowing
   (`let Some(e) = ce.as_event() else { continue };`) or through `item()` where the logic is
   genuinely kind-agnostic. **No `unwrap()` on `as_event()`.**
3. `git diff --stat` shows **zero** changes under `#[cfg(test)]` blocks of existing event tests.
   (R104)
4. `just check` clean under `-D warnings`; `just test` green at 686.
5. Sync direction logic in `calendar_diff.rs` is textually unchanged apart from the accessor
   rename — three-way-vs-base first, then mtime/`LAST-MODIFIED` fallback. (R2, R40)

## Non-goals

- **Do not** add task handling, kind-awareness, or a `match` on `CalendarItem` that does anything
  different per kind. Tasks cannot reach these sites yet.
- **Do not** delete the legacy `event()` accessor — `L2-06`.
- **Do not** "improve" the narrowing into a filter that silently drops items. A silent drop feeds
  the delete path (R48/C7); if a site genuinely cannot handle a non-event, leave a
  `TODO(L2-06/L3-03)` and keep the current behaviour.
- **Do not** change `occurs_in_range` (`event.rs:136-141`) — R45 requires it byte-for-byte
  unchanged.
- **Do not** touch `caldir-cli` or the provider crates. Those are `L2-04`/`L2-05`, running in
  parallel on disjoint crates.

## Verification

```sh
just check
just test
cargo test -p caldir-core --lib
```
Run **serially**. Two concurrent cargo invocations race rustup on the pinned `1.97.0` toolchain
and corrupt it (`context/testing.md` §1).

## Notes for the implementer

- Landmarks in `calendar_diff.rs`: remote map built by `.collect()` at `:25-28`; pass-1 compare at
  `:36`→`:38`; the `Update` emission at `:63`; delete inference at `:86` and `:110`; the
  three-way-vs-base direction call at `:153`; equality-driven "content changed?" at `:37`,
  `:155-166`. These lines are the reason the 686 baseline is the gate — a wrong narrowing here is
  invisible until a user loses data.
- `caldir-core/src/calendar.rs:114` (`events.push(CalendarEvent::load(path)?)`) is the poison-pill
  `?`. It is **`L0-01`/`L2-07`'s**, not yours — do not restructure it.
- If a `calendar/state/*.rs` file fails to compile, the minimum fix is the accessor rename; do not
  rework the base/known-id layout. That is `L1-06` + `L3-01`.
- `caldir-core/src/test_utils.rs` is crate-private (`lib.rs:11-12`), so anything you add there is
  invisible to `caldir-cli` and the providers.
- CI runs the suite under `TZ=UTC`, `TZ=Europe/Stockholm`, `TZ=America/New_York`
  (`fail-fast: false`). A pure accessor rename should be TZ-neutral; if a TZ-specific failure
  appears, you changed behaviour somewhere.
