# L1-06: identity gains `ComponentKind`; the `VTODO:` sigil

**PR-2.** ⚠ This ticket changes an **on-disk contract** (`state/known_event_ids`). INDEX §5 strongly
advises landing it together with `L3-01` (the `bases/` rehash): the sigil without rehashed bases
leaves a state directory whose filenames no longer match their contents. Recoverable (bases degrade
to "no base"), but it costs users a full re-sync. Coordinate before merging alone.

## Responsibility
`EventInstanceId` carries the component kind. The **string form stays byte-identical for events** and
gains a `VTODO:` prefix for tasks; parsing stays infallible. `known_event_ids` keeps writing one
sorted id per line in the same file, now including task lines.

## Requirements satisfied
- **R36 (INVIOLABLE)** — *"Item identity MUST carry the component kind: `(kind, uid, Option<recurrence_id>)`. A component-agnostic key is not acceptable (ADJUDICATION C-1…). Five hazards, all real and all closed by one enum field"* — state-file collision, diff mis-keying, wrong-component deletion, base-file overwrite, `doctor` false positive.
- **R37** — *"The identity **string form** MUST be byte-identical to today for events (`{uid}` / `{uid}__{rid}`) and carry a kind sigil for tasks (`VTODO:{uid}` / `VTODO:{uid}__{rid}`). Parsing stays infallible: strip a leading `VTODO:` if present, else treat the whole string as an event id, then apply the existing rid split. Accepted residual: a VEVENT whose UID literally begins with `VTODO:` round-trips as a task — the same ambiguity class already accepted for `__`…"*
- **C4 (AMENDED, INVIOLABLE for the event form)** — *"Line format stays one id per line, sorted, plaintext; the file keeps being written; task ids go in the **same** file… (a) existing unprefixed lines still parse as kind `Event`, byte-identical; (b) an older caldir treats a `VTODO:`-prefixed line as an inert unknown id that cannot trigger a delete."*

## RED tests
- **ADD** `event::instance_id::tests::parse_of_format_is_identity_for_both_kinds` (**T-20**, R36/R37)
  in `caldir-core/src/event/instance_id.rs`. Per spec §18 it MUST cover **all four rid sub-forms**
  (all-day `YYYYMMDD`, UTC `…Z`, floating, zoned `TZID=…`), **a UID containing `__`**, and **the
  pathological `UID:VTODO:x` event**. For each: `format` then `parse` yields the same id *including
  its kind*, and the event forms are byte-identical to today's strings. Right proof: identity is a
  `HashMap` key across the sync engine and the state files — a non-injective round trip silently
  merges two items, which is R36 hazards 1-4. The pathological case is included because R37 *accepts*
  that residual; the test records the accepted behaviour rather than pretending it cannot happen.
- **ADD** `calendar::state::known_event_ids::tests::event_form_lines_are_byte_identical_and_task_lines_are_prefixed`
  (**T-21**, C4 amended) in `caldir-core/src/calendar/state/known_event_ids.rs`. Asserts (a) an
  existing unprefixed line loads as kind `Event` and re-writes byte-identically, and (b) a task id
  writes as `VTODO:…` into the **same** file, one per line, sorted. Right proof: C4 is INVIOLABLE for
  the event form, and the downgrade argument in B-4 depends on the file staying one-id-per-line
  plaintext so an older caldir sees a task line as an inert unknown id.
- **KEEP GREEN, UNEDITED**: all existing `instance_id` round-trip tests (`:125-230`). They are the
  R37 byte-identity guard.

## Acceptance criteria
1. `EventInstanceId` carries a `ComponentKind` (two variants today, extensible to VJOURNAL as one
   more variant — R93). (R36)
2. `Display` for an event id emits exactly `{uid}` / `{uid}__{rid}` as today; for a task,
   `VTODO:{uid}` / `VTODO:{uid}__{rid}`. (R37)
3. `From<&str>` remains **infallible**: strip a leading `VTODO:` if present, else treat the whole
   string as an event id, then apply the existing rid split — in that order. (R37)
4. `known_event_ids` still writes one sorted plaintext id per line to the same path; event lines are
   byte-identical to before. (C4)
5. T-20 and T-21 pass; every pre-existing `instance_id` test passes unmodified. (R37, R104)
6. `just check` and `just test` green, 686 baseline unmodified.

## Non-goals
- **Do not** rehash or migrate `state/bases/<sha256>.ics` — that is `L3-01` (advised same PR, but its
  own ticket, and C5's skip-on-unparseable path is its responsibility).
- **Do not** make the diff kind-aware (`L3-03`) or fix `doctor`'s duplicate detection (`L2-08`), even
  though R36 lists them as hazards this field *enables* closing.
- **Do not** invent a kind-distinct CalDAV href. ADR-02 rule #4 is **struck**: the href stays
  `{uid}.ics` for both kinds, because Radicale 409s a same-UID resource at a different href
  (ADJUDICATION C-1).
- **Do not** attempt to remove the `VTODO:`-prefixed-UID ambiguity with an escaping scheme. R37
  accepts it explicitly; UID is `TEXT` and no encoding removes it.
- **Do not** rename `EventInstanceId` or the other `Event*`-prefixed shared types — R94, deferred.

## Notes for the implementer
- `EventInstanceId::new(uid, rid)` has ~15 call sites across the workspace (production sites include
  `event.rs:253` and `instance_id.rs:65,71`; the rest are tests). Decide the constructor shape so
  existing **event** call sites read unchanged — e.g. keep `new` meaning "an event id" and add a
  kind-taking constructor — rather than forcing a mechanical edit through every test.
- **Parse order matters.** Strip the sigil **first**, then apply the rid split; doing it the other
  way mangles a task whose UID contains `__`.
- The C4 downgrade argument (B-4) holds only because a delete needs the id present on exactly one
  side (`calendar_diff.rs:86` / `:110`) and no VEVENT produces a `VTODO:`-prefixed id. Do not
  introduce any code path where an event can format with the sigil.
- `KnownEventIds` is a `HashSet<EventInstanceId>` (`:21`) — adding a field changes `Hash`/`Eq`, which
  is the point (hazard 1). Confirm the sorted output stays deterministic; `write_from` sorts strings,
  so task lines sort under `V`, which is fine and must not be "fixed" by a custom ordering.
- Conventions: inline `#[cfg(test)] mod tests`, no fixture files,
  `use pretty_assertions::assert_eq;`. CI: `-D warnings` on `just check`; TZ matrix on `just test`.
