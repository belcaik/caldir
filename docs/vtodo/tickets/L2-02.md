# L2-02 — expand: `CalendarEvent` stores a `CalendarItem`

**Layer:** L2 · **PR-2** · **Depends on:** `L2-01`, `L1-07`

## Responsibility

Retype `CalendarEvent`'s private field from `Event` to `CalendarItem` and add the new accessors
`item() -> &CalendarItem` and `as_event() -> Option<&Event>`. **Keep the legacy
`event() -> &Event` accessor temporarily.** It is unreachable for tasks in this ticket — the
loader still cannot produce a `CalendarItem::Todo` until `L2-06` — so it can safely unwrap, and
CI stays green with **zero call-site churn** across ~70 sites in three crates.

The write path (`create`, `update`, `delete`, `write_best_event_file`, `sync_file_mtime`) must
work for either kind: filename via the kind's own slug rule, body via the kind's own
`to_ics_string()`.

## Requirements satisfied

- **R11** — "Identity is derived from ICS content, never from a filename; a rename MUST NOT look
  like delete-plus-create to sync."
- **R32 (writer safety)** — "A local `.ics` file MUST contain **exactly one supported
  component** … The writer is unchanged and keeps writing exactly one serialized item; R32 is
  what makes that safe."
- **R100 (partial)** — a mixed local directory keeps both items distinct; the write path must not
  collapse a task onto an event's path.

## Required context

- `spec.md` §5 (R10, R11), §9 (R32, R33–R34 filename rules).
- `adr/ADR-03-file-model.md` §Decision item 4 ("The writer is **not** changed") and §Context
  paragraph beginning "**The writer cannot preserve what it did not change.**"
- `adr/ADR-01-component-abstraction.md` §Consequences — the containment strategy:
  *"keep `CalendarEvent::event() -> Option<&Event>` as a narrowing accessor so VEVENT-only callers
  change by adding a `let Some(e) = .. else { continue }` rather than being rewritten."*
- `L1-07`'s ticket — task filenames (`_task__…`) already exist; call them, don't re-derive them.

## Acceptance criteria

1. `CalendarEvent`'s stored field is `CalendarItem`. (R32)
2. `item()` and `as_event()` exist and are public; `event()` still exists, still returns
   `&Event`, and is documented in a one-line comment as *temporary, removed in L2-06*.
3. Not a single call site outside `caldir-core/src/calendar/event.rs` changes in this commit.
4. `CalendarEvent::update` and `create` derive the filename from the item's own kind
   (`Event::base_slug()` for events — **byte-identical**, C1; `L1-07`'s task slug for tasks) and
   the body from the item's own `to_ics_string()`. (R33, R34)
5. `sync_file_mtime` still receives the item's `last_modified` for both kinds.
6. The new byte-identity test passes; `just check` and `just test` are green.

## Non-goals

- **Do not** delete `event()`. That is `L2-06` and removing it here breaks three crates at once.
- **Do not** change `Calendar::events()`, `Calendar::event(slug)`, or `event_by_instance_id`.
  They are `L2-03`/`L2-07`.
- **Do not** make `CalendarEvent::load` return a task. `load` still errors on a VTODO after this
  ticket — that is correct and expected; `L2-06` flips it.
- **Do not** invent a multi-item file model. ADR-03 option B is rejected: the writer would have
  to re-serialize untouched siblings through known-lossy paths.
