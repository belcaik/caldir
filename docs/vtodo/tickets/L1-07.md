# L1-07: task filenames

**PR-2.**

## Responsibility
Give `Todo` a base slug following the existing reserved-prefix convention — `_task__recurring__…`,
`_task__{time_slug}__{summary_slug}`, `_task__{summary_slug}` — reusing the existing `time_slug`
and summary-slug logic **verbatim**. `Event::base_slug()`'s output is not touched, for any input.

## Requirements satisfied
- **R33** — *"Event filenames MUST be byte-identical to today for every input that is an event today (§15 C1, INVIOLABLE)."*
- **R34** — *"Task filenames MUST extend the existing reserved-prefix convention (`_recurring__`, `slugify.rs:15`):"* recurring ⇒ `_task__recurring__{summary_slug}.ics`; dated ⇒ `_task__{time_slug}__{summary_slug}.ics`, **date source `DUE`, falling back to `DTSTART`**; undated ⇒ `_task__{summary_slug}.ics`. *"`time_slug()` is reused verbatim (`%Y-%m-%d` for a date, local-tz `%Y-%m-%dT%H%M` for a datetime). `__` is the only separator the summary slugifier can never emit…"*
- **R35** — *"Because `time_slug` is local-timezone-dependent, task filename tests MUST run under the CI TZ matrix (R106)."*
- **C1 (INVIOLABLE)** — *"No VEVENT file renamed, rewritten, or re-serialized as a side effect. `base_slug()` byte-identical for every input that is an event today."*

## RED tests
Both live in `caldir-core/src/event/slugify.rs`'s test module (spec §18 places them there — see
Notes) and both are **TZ-marked (R106)**.

- **ADD** `event::slugify::tests::base_slug_is_unchanged_for_vevent_corpus` (**T-6**, R33/C1).
  Spec §18 specifies **~12 pairs** covering at least: all-day, recurring master, empty summary,
  emoji, and a >64-character summary. Each asserts the produced slug equals a **literal expected
  string**. Right proof: C1 is INVIOLABLE and its failure mode is a mass rename of every user's files
  on next write. Asserting against literals — not against `Event::base_slug()` re-invoked — is what
  makes the test a lock rather than a tautology.
- **ADD** `event::slugify::tests::task_filenames_cover_recurring_dated_and_undated` (**T-7**,
  R34/R35). One case per row of R34's table, plus a dated task with **both** `DUE` and `DTSTART`
  asserting `DUE` wins, and one with `DTSTART` only asserting the fallback. Right proof: the date
  source rule is the only part of R34 that can be implemented backwards while still producing
  plausible filenames, and `time_slug` is local-tz so the expected strings differ per zone — hence
  the TZ matrix.

## Acceptance criteria
1. All three R34 rows produce exactly the specified names, with `_task__` as the reserved prefix and
   `__` as the separator. (R34, T-7)
2. Date source is `DUE`, falling back to `DTSTART`; an undated task gets **no** date component and no
   fabricated one. (R34, R46)
3. `time_slug` formatting is reused verbatim — `%Y-%m-%d` for a date value, local-tz `%Y-%m-%dT%H%M`
   for a datetime — not reimplemented. (R34)
4. `Event::base_slug()` output is byte-identical for every input, proved by T-6's literal corpus.
   (R33, C1)
5. Both tests pass under `TZ` = `UTC`, `Europe/Stockholm`, `America/New_York`. (R35, R106)
6. `just check` and `just test` green, 686 baseline unmodified. (R104)

## Non-goals
- **Do not** change `Event::base_slug()`, `summary_slug()`, the `untitled` fallback, the emoji strip,
  or `crate::utils::slugify`'s length cap. C1 is INVIOLABLE. Extracting a helper is permitted **only**
  if T-6 proves the output is unchanged.
- **Do not** wire task filenames into `CalendarEvent::create/update` — the writer becomes item-aware
  in `L2-02`/`L2-06`.
- **Do not** add a migration or rename pass for existing files.
- **Do not** invent a filename-derived identity. Identity comes from ICS content, never a filename
  (R11); a rename must not look like delete-plus-create.
- No `doctor` duplicate handling (`L2-08`), no agenda rendering (`L7-02`).

## Notes for the implementer
- **INDEX says "shared helper visibility only" for `event/slugify.rs`; that is not literally
  achievable.** `time_slug()` and `summary_slug()` are *private methods on `Event`* that read
  `self.start` and `self.summary` (`slugify.rs:21`, `:47`). A `Todo` has neither field in that shape
  (its date source is `DUE`-then-`DTSTART`, and both are `Option`). Extract them as `pub(crate)` free
  functions taking `&EventTime` / `Option<&str>`, have `Event`'s methods delegate, and let T-6 prove
  the output did not move. Do not duplicate the formatting logic — R34 says "reused verbatim".
  Flag this deviation from the INDEX row in your handoff.
- **Zone trap.** `to_local_tz(&Local)` means the same instant yields different filenames in different
  zones — by design (`slugify.rs:44-46` explains why). Expected strings in T-7 must therefore either
  use `EventTime::Date` / `DateTimeFloating` fixtures (testing.md §11's advice) or compute the
  expectation from the same local conversion. Do **not** hardcode a UTC-derived name and then "fix"
  the test by pinning `TZ=UTC` — that defeats R35.
- Undated means undated: no epoch, no `COMPLETED`, no "now". R46 is INVIOLABLE and a synthesized date
  here would also leak into the window predicate later.
- `__` is the only separator the summary slugifier can never emit, which is what makes
  `_task__recurring__x` unambiguous against a task titled "recurring x". Do not switch separators.
- Conventions: inline `#[cfg(test)] mod tests`, no fixture files,
  `use pretty_assertions::assert_eq;`. CI: `-D warnings` on `just check`.
