# L7-04 — RSVP and invites narrow to events

## Responsibility

`rsvp` and `invites` are **meaningless on a task**. Single-file `rsvp` on a VTODO file must fail with a
message naming the cause, exit non-zero, and **write no file**. List/interactive `rsvp` and `invites` must
narrow to events so a task never enters the invite list.

## Requirements satisfied

- **R81** (verbatim): *"RSVP on a task is meaningless. Single-file mode MUST fail naming the cause
  (`"<path> is a task, not an event; tasks cannot be RSVP'd"`), exit non-zero, and **write no file**. List
  mode MUST narrow to events so tasks never enter the invite list; same for `invites`."*
- **C13** (INVIOLABLE) for the untouched paths: RSVP on an *event* keeps its exact current text and exit code.

## Dependencies

`L2-04` (CLI call sites migrated to `CalendarItem`; `CalendarEvent::event()` narrows to `Option<&Event>`).

## RED tests

**`T-42` — `caldir-cli/src/commands/rsvp.rs`, `mod tests`:**
`commands::rsvp::tests::rsvp_on_a_task_exits_non_zero_and_leaves_the_file_unmodified`

Write a VTODO `.ics` into a temp calendar directory, record its exact bytes **and** its mtime, invoke the
single-file rsvp path against it, then assert three things:
1. the call returns `Err` (non-zero exit) — not `Ok` with a printed warning;
2. the error message is exactly `"<path> is a task, not an event; tasks cannot be RSVP'd"` with `<path>`
   substituted — R81 quotes the string, so assert on it, not on a substring like "task";
3. the file's bytes are **byte-identical** to what was written.

Assertion 3 is the load-bearing one: the failure mode this test exists to catch is failing *after* the
`update` at `rsvp.rs:56` has already rewritten the file.

Add: `commands::invites::tests::a_task_never_enters_the_invite_list` — a calendar holding one task carrying
an `ATTENDEE` (permitted by C-2) plus one genuine event invite; assert the collected invite list has exactly
one entry and it is the event.

## Acceptance criteria

1. `run_direct` checks the loaded item's kind **before** any mutation and bails with the R81 message.
2. The bail happens before `cal_event.update(...)`; no write, no partial write, no temp file left behind.
3. The exit status is non-zero (an `anyhow::bail!` propagated out of `run`, matching the other failure
   paths at `rsvp.rs:18-21` and `:28-30`).
4. `run_interactive` narrows with `let Some(event) = ce.event() else { continue };` — tasks are skipped, not
   rendered, not counted in the "Found N pending invites" total, and not passed to `sort_by_key`.
5. `invites::run` applies the same narrowing; a task carrying `ATTENDEE` never appears.
6. RSVP against an **event** produces byte-identical output and the same exit code as before (C13).
7. `cargo test -p caldir-cli -- rsvp invites` green; zero edits to existing event tests (R104).

## Non-goals

- Any task-specific completion command (`caldir done`, etc.) — not in the MVP, no ADR owns it.
- Teaching `resolve_rsvp` in `output/agenda.rs` about tasks (that narrowing belongs to `L7-01`).
- Changing `ATTENDEE` modelling on `Todo` — it is IN per C-2 and stays IN; only the *invite semantics* are
  narrowed here.

## Notes for the implementer

- **Trap — order of operations.** `run_direct` currently loads (`:46`), reads `.event()` (`:47`), checks
  `is_invite_for` (`:49`), then writes (`:56`). Put the kind check immediately after the load. Any later and
  a task can reach `apply_response` / `update`.
- **Trap — the message.** R81 quotes it character for character. `"<path> is a task, not an event; tasks
  cannot be RSVP'd"` — note the semicolon and the apostrophe in `RSVP'd`. Do not reword it.
- **Trap — silently skipping in single-file mode.** `continue`-style narrowing is correct for *list* mode
  and wrong for single-file mode: the user named that file explicitly, so a silent no-op-with-exit-0 is the
  silent-drop class the spec rules against everywhere (B-3, C10).
- `sort_by_key(|(_, _, ce)| ce.event().start.to_utc())` at `rsvp.rs:102` will not compile once `event()`
  returns `Option<&Event>`. Because the list is already narrowed upstream, store the `Event` alongside the
  `CalendarEvent` rather than re-unwrapping inside the sort key.
- Toolchain `1.97.0`; clippy `-D warnings`; CLI tests use `indoc`; never run two cargo commands in parallel.
