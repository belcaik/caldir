# L5-00 — extract the CalDAV REPORT bodies into pure functions

## Responsibility

The `calendar-query` REPORT XML that caldir sends to a CalDAV server is built **inside**
`DavRequest::prepare_request`, a private trait-impl method that takes a `Uri` and immediately
folds the body into a `Request::builder()`. Nothing outside a live transport can see those bytes.

Extract each body into a **pure `fn -> String`**, have `prepare_request` call it, and change
**nothing** about the bytes emitted. This is a refactor with no behaviour, no new dependency and
no core-API contact.

## Requirements satisfied

None of its own — this is enabling infrastructure, in the same class as `L0-04`.

It is the precondition for four tests that are otherwise **unwritable**:

- `T-37` `caldav::ops::list_events::tests::the_vtodo_report_body_contains_no_time_range` (`L3-02`)
- `T-38` `caldav::ops::list_events::tests::the_vtodo_report_is_a_separate_request_from_the_vevent_report` (`L3-02`)
- `T-39` `caldav::ops::tests::find_event_location_is_component_aware_on_both_paths` (`L5-02`)

## Shape

Two free functions in the module that owns each request, `pub(crate)` at most:

```rust
/// Body of a CalDAV `calendar-query` REPORT for one component kind.
/// `range` is `Some((start, end))` for a time-ranged query, `None` for a bare comp-filter.
pub(crate) fn calendar_query_body(component: &str, range: Option<(&str, &str)>) -> String

/// Body of the UID-lookup `calendar-query` REPORT for one component kind.
pub(crate) fn uid_lookup_body(component: &str, uid: &str) -> String
```

`component` is `"VEVENT"` or `"VTODO"`; `range: None` emits a `<C:comp-filter name="…"/>` with no
child. Today every caller passes `"VEVENT"` and a `Some(range)` / a uid, so the emitted bytes are
unchanged by construction.

## Tests

**New — `caldir-provider-caldav/src/caldav/ops/list_events.rs`, `mod tests`:**
`caldav::ops::list_events::tests::the_vevent_report_body_is_unchanged_by_the_extraction`

A golden-string lock: assert `calendar_query_body("VEVENT", Some(("20260101T000000Z",
"20261231T235959Z")))` equals the exact XML the current `prepare_request` interpolates, byte for
byte, including indentation and the `xmlns` attribute order. Add the mirror assertion for
`uid_lookup_body("VEVENT", "some-uid@example")`.

This is the whole point of the ticket: the refactor is only safe if it is provably inert, and the
only way to prove that is to freeze the output before anything else in `L5` moves.

## Acceptance criteria

1. Both `prepare_request` impls contain **no** `format!` of XML — they call the extracted function
   and do nothing but build the `Request`.
2. The extracted functions are pure: no `Uri`, no `self`, no I/O, no `Result`.
3. `component` is a parameter, not a constant, on both — `L3-02` and `L5-02` pass `"VTODO"`
   through it; neither should have to re-open this file.
4. `range: None` produces a self-closing `<C:comp-filter name="VTODO"/>` with **no**
   `<C:time-range>` child anywhere in the document. This is R51/R58's structural half; `L3-02`
   owns the decision to *use* it.
5. The golden-string test passes, and the emitted bytes for the `VEVENT` calls are identical to
   the pre-refactor bytes.
6. `cargo test -p caldir-provider-caldav` and `just test` green.

## Non-goals

- **Emitting a VTODO query.** That is `L3-02`, and it may not be split from the R44 window rule
  (see INDEX §5). This ticket only makes the component a parameter.
- Making `find_event_location` component-aware — `L5-02`.
- Any change to `parse_event`'s silent drop — `L5-01`.
- Any new dev-dependency. This ticket needs no HTTP double at all; that is exactly its value if
  the `wiremock` decision (INDEX §0a ④) goes the other way.

## Notes for the implementer

- **Trap — "it's only two `format!`s, fold it into `L3-02`".** It gates two tickets in two
  different chains (`L3-02` in the sync spine, `L5-05` at the end of the CalDAV spine). Folded
  into either one, the other silently inherits an unwritable test. It also has zero dependencies,
  so as a standalone node it costs nothing on the critical path.
- **Trap — tidying the XML while you are in there.** Do not reindent, reorder attributes, or
  "fix" the namespace declarations. The golden-string test will catch you, but the reason it will
  catch you is that a reordered attribute is a real wire change against real servers.
- The two bodies are structurally similar but not identical (one nests `<C:time-range>`, the other
  `<C:prop-filter>`). Resist unifying them behind one function with an enum — two small pure
  functions read better and `L3-02`/`L5-02` each touch only one.
- Toolchain `1.97.0`; clippy `-D warnings`; never run two cargo commands in parallel.
