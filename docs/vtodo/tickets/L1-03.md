# L1-03: Todo ICS parsing for the MVP property set

**PR-2.**

## Responsibility
`VTODO` → `Todo`. One direction only: parsing. Read `STATUS` and `PRIORITY` from the **raw**
properties, read `COMPLETED` with caldir's own time parser, normalize inbound TZIDs to IANA on
`DUE`/`DTSTART`, capture `X-*` with the same filter events use, and require **no** `DTSTART`.

## Requirements satisfied
- **R13** (IN-set parse) — *"The task type MUST model exactly the IN set and MUST NOT model the OUT set."* Including its `PRIORITY` row: *"MUST NOT use `Component::priority()` — clamps to `0..=10`, returns `None` above. Out-of-range MUST round-trip verbatim."* and its `STATUS` row: *"MUST parse the **raw** property — `get_status()` drops unknown values"*, and its `COMPLETED` row: *"MUST NOT use `get_completed()` — returns `None` for a non-UTC value while retaining the raw property (C5). Use caldir's own time parser."*
- **R14** — *"An unknown `STATUS` value MUST NOT silently become the default: it round-trips verbatim, or it is dropped with the loss pinned by a test (T-14)."*
- **R20** — *"A task MUST NOT require `DTSTART`. The event rule (`EventError::MissingStart`, `event/from_icalendar.rs:11`) stays unchanged for events and MUST NOT apply to tasks."*
- **R21** — *"`DUE;TZID=…` MUST round-trip with its TZID intact… Inbound TZIDs are normalized to IANA at the parse boundary, per the existing project rule."*
- **R22** — *"A floating (non-UTC) `COMPLETED` MUST be read by caldir's own parser and MUST NOT be silently lost — `get_completed()` returns `None` for it while the raw property is retained, so "present but unreadable" is reachable (C5)."*
- **R23** — *"Parsing MUST capture `X-*` with name, value, and parameters using the same filter events use, and MUST NOT capture any non-`X-` property into a passthrough bag."*
- **R68** — *"Radicale imposes no semantic coupling: `STATUS:COMPLETED` without `PERCENT-COMPLETE` is accepted `201` and stored verbatim, as is the contradictory `STATUS:COMPLETED` + `PERCENT-COMPLETE:0`… caldir MUST NOT synthesize either to "repair" the other."*

## RED tests
All three are new; none of the five VTODO RED tests goes green here.

- **ADD** `todo::from_icalendar::tests::zoned_due_and_floating_completed_round_trip` (**T-13**,
  R21/R22) in `caldir-core/src/todo/from_icalendar.rs`. **TZ-marked (R106)** — it must pass under
  `UTC`, `Europe/Stockholm` and `America/New_York`. Asserts the zoned-`DUE` fixture parses with its
  TZID intact (IANA form) and that a floating `COMPLETED` is read, not `None`. Right proof because
  both properties have a crate-provided accessor that quietly returns `None` for exactly these
  inputs — the failure is silent data loss, and it is zone-sensitive.
- **ADD** `todo::tests::an_unknown_status_value_is_preserved_or_explicitly_dropped` (**T-14**, R14)
  in `caldir-core/src/todo.rs`. Asserts that an unrecognised `STATUS` does **not** silently become
  `NEEDS-ACTION`-by-accident but is dropped as a **pinned, documented** loss. Right proof: R14's
  whole point is that the default-on-unknown behaviour is invisible; only an explicit assertion
  distinguishes "we chose to drop it" from "we did not notice".
- **ADD** `todo::tests::priority_out_of_rfc_range_round_trips_verbatim` (**T-15**, R13 PRIORITY row)
  in `caldir-core/src/todo.rs`. Asserts `PRIORITY:42` survives parse (and re-serialization once
  `L1-04` lands) unchanged. Right proof: `Component::priority()` returns `None` above 10, so the
  natural implementation destroys the value.

## Acceptance criteria
1. A VTODO with no `DTSTART` parses successfully; `EventError::MissingStart` is never produced for a
   task, and `event/from_icalendar.rs:11` is unmodified. (R20, R2)
2. `STATUS` is read from the raw property, not `get_status()`; an unknown value is handled per R14
   with T-14 pinning the outcome. (R13, R14)
3. `PRIORITY` is read raw; `PRIORITY:42` survives. (R13, T-15)
4. `COMPLETED` is read by caldir's own time parser and a floating value is retained. (R22, T-13)
5. `DUE`/`DTSTART` TZIDs are normalized to IANA at the parse boundary, matching the event path. (R21)
6. `X-*` capture uses the same `starts_with("X-")` filter and keeps name, value **and parameters**;
   no non-`X-` property is captured anywhere. (R23)
7. Nothing is synthesized: no `PERCENT-COMPLETE` invented from `STATUS:COMPLETED` or vice versa,
   no fabricated dates. (R68, R46)
8. `just check` green, the three tests pass under all three timezones, `just test` 686 baseline
   unmodified. (R104, R106)

## Non-goals
- **No serialization** — `Todo → ICS` is `L1-04`. Where a test needs a round trip, sequence this
  after `L1-04` or assert on the parse half only.
- **No `CalendarItem`, no dispatch, no arity rules, no `VTIMEZONE` handling** — `L2-01` owns the
  one-ordered-pass parser and R17/R18/R19. This ticket converts a single `icalendar::Todo` it is
  handed.
- **No `RELATED-TO` / `CATEGORIES` parsing** — both OUT (R87, R88). `L1-05` pins the loss.
- **Do not touch `event/from_icalendar.rs`**, and do not "share" the event conversion by generifying
  it. R2 is INVIOLABLE and the field sets genuinely differ.
- No equality (`L1-02`), no filenames (`L1-07`), no window predicate (`L3-02`).

## Notes for the implementer
- **The three named traps, all verified, all silent:** `get_status()` drops unknown values;
  `Component::priority()` clamps to `0..=10` and returns `None` above; `get_completed()` returns
  `None` for a non-UTC value **while the raw property is still there**. Each one compiles, runs, and
  loses data. Read the raw `Property` in all three cases.
- **R14 is already decided by `L1-01`.** `TodoStatus` is strictly four-valued, so "round-trips
  verbatim" is not available — implement "dropped, with the loss pinned by T-14", and say so in the
  test's comment.
- **Probe hygiene (R108)** if you build a scratch crate to check crate behaviour: pin
  `icalendar = "=0.17.10"`, print the resolved version, and echo the exact input bytes sent. Two
  probes in this effort produced wrong answers from unexamined inputs (one resolved 0.17.13 behind a
  caret requirement; one used bash `printf` and measured a fixture with no `COMPLETED` property at
  all). *A probe that returns the answer you expected is not evidence until you have inspected the
  input it actually sent.*
- `DTSTAMP` is parsed and **discarded** — it must not become a field (R25). Same for anything in the
  OUT set.
- TZ-sensitivity is real: a floating `COMPLETED` and a zoned `DUE` resolve differently per zone. Use
  the `TZ3` loop above, not a single run.
- Conventions: inline `#[cfg(test)] mod tests`, inline `\r\n` fixtures from `test_utils`, no fixture
  files, `use pretty_assertions::assert_eq;`.
