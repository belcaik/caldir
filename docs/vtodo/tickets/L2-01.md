# L2-01 — expand: `CalendarItem` + the one-ordered-pass parser, as a *new* API

**Layer:** L2 (component abstraction) · **PR-2** · **Depends on:** `L1-03`, `L1-04`, `L0-04`

## Responsibility

Add `pub enum CalendarItem { Event(Event), Todo(Todo) }` in `caldir-core/src/item.rs` and
`CalendarItem::from_ics_str`, which makes **one ordered pass** over
`icalendar::Calendar.components` (a public field, `icalendar-0.17.10/src/calendar.rs:71`):
`VEVENT → Event`, `VTODO → Todo`, `VTIMEZONE → ignored for counting`, **anything else → a hard
error naming it**. Add the arity vocabulary that distinguishes "none" from "too many".

`Event::from_ics_str` / `from_single_ics_str` **keep their current signatures** and delegate to
the new pass, discarding tasks. Nothing else in the workspace changes yet. This is the *expand*
half of expand→migrate→contract; the contract flip is `L2-06`.

## Requirements satisfied

- **R7 (INVIOLABLE)** — "An item's kind is determined solely by the component it was parsed from
  and is preserved across every boundary."
- **R10** — "One `.ics` file holds exactly one supported component (R32)."
- **R17** — "Parsing MUST make **one ordered pass** over the document's components, dispatching
  `VEVENT -> event`, `VTODO -> task`, everything else -> R19. One pass, not `events()` then
  `todos()`, so document order survives."
- **R18 (disk loader half)** — "`VTIMEZONE` MUST be ignored for counting and MUST NOT be treated
  as unsupported."
- **R19 (INVIOLABLE)** — "An unsupported data-bearing component (`VJOURNAL`, `VFREEBUSY`,
  unknown, `X-`) MUST produce a **hard error naming the component** — never a silent skip, never
  an empty vector. A silent drop feeds the delete path (R48, §15 C7/C10)."
  **This is inviolable and breaches C10 if softened. ADR-01 decision step 5's `_ => skip` is
  STRUCK by ADJUDICATION B-3. There is no `_ => skip` arm in this ticket, ever.**
- **R32** — "A local `.ics` file MUST contain **exactly one supported component**."
- **R75** — the error vocabulary: **too many** = "expected exactly one VEVENT or VTODO in
  `{path}`, found `{n}`; split it into one file per item"; **none** = "no VEVENT or VTODO in
  `{path}` (found: `{names}`)", `{names}` listing the components present or the literal
  `nothing`.
- **R76** — the wire/sync-base error type gains the arity variant and SHOULD NOT duplicate the
  "none" variant.
- **R93** — VJOURNAL must stay one variant + one struct + one match arm away.
- **R101** — a VEVENT+VTODO file "MUST error naming the count and MUST NOT load with the VTODO
  silently dropped".

## Acceptance criteria

1. `CalendarItem` exists in `caldir-core/src/item.rs`, is re-exported from `lib.rs` (which today
   exports at `caldir-core/src/lib.rs:14-25`), and has exactly two variants. (R7, R93)
2. Dispatch is a single ordered `for`/`match` over `icalendar.components`; `icalendar::Calendar::events()`
   is **not** called by the new path. Document order is preserved. (R17)
3. `CalendarComponent` is `#[non_exhaustive]`, so a `_` arm is required — that arm **errors and
   names the component**, it does not skip. (R19)
4. `VTIMEZONE` is excluded from the count and produces no error. (R18)
5. `EventError` gains `UnexpectedComponentCount { expected, found }` and
   `CalendarEventError` gains `ExpectedSingleComponent { path, found }` +
   `NoSupportedComponent { path, found: String }` with the R75 wording verbatim. `found: "nothing"`
   for a component-less `VCALENDAR`. (R75, R76)
6. `Event::from_ics_str` and `Event::from_single_ics_str` still return
   `Result<Vec<Result<Event, EventError>>, _>` / `Result<Event, _>` respectively. **Zero call-site
   churn ships in this ticket.** (containment; `L2-06` flips them)
7. `T-9` passes; `T-1` compiles and is still red; `SUITE` is green.

## Non-goals

- **Do not** retype `Event::from_ics_str`, `CalendarEvent`, `Calendar::events()`, the RPC codec,
  or anything downstream. That is `L2-02`/`L2-06` and doing it here collapses the migrate batches.
- **Do not** try to make `T-1`, `T-2`, `T-3`, `T-4` or the load-a-VTODO half of `T-8` green.
  They are `L2-06`/`L2-07`'s green moment by design (ADJUDICATION §SEQUENCING NOTE).
- **Do not** touch `Event`'s `PartialEq`, `occurs_in_range`, `base_slug`, or either codec (R2/C2).
- **Do not** add a `VJournal` variant (R93 says *do not preclude*, not *implement*).

## Notes for the implementer

- The single dispatch point that drops every VTODO today is
  `caldir-core/src/event.rs:101`: `Ok(icalendar.events().map(Event::try_from).collect())`.
  Verified probe on the fixture: `components=1 events=0 todos=1`.
- `icalendar::Todo` carries the *same* trait stack as `icalendar::Event`
  (`component_impl!{Todo,"VTODO"}` + `event_impl!{Todo}`), so the shared codec half is one generic
  fn pair over `T: EventLike` — `L1-03`/`L1-04` already built the `Todo` side; reuse it.
- **Never call `ends()`/`all_day()` on a `Todo`** — `icalendar` 0.17.10 emits an RFC-invalid
  `DTEND` (R8, verified on pinned `=0.17.10`).
- Unknown components surface as `CalendarComponent::Other(kind)` with a readable name on
  `=0.17.10` (verified, ADJUDICATION B-3), so `NoSupportedComponent { found }` really can name them.
- `caldir-core/src/test_utils.rs` is `#[cfg(test)] mod test_utils;` (`lib.rs:11-12`) — **crate-private**.
  `caldir-cli` and the provider crates cannot use its fixtures.
- CI runs `-D warnings` and a TZ matrix (`UTC`, `Europe/Stockholm`, `America/New_York`). Nothing
  in this ticket is time-dependent, but clippy pedantry on a new public enum is a real failure mode.
