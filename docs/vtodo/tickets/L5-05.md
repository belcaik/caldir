# L5-05 — the live Radicale tier

**Layer:** L5 (CalDAV provider) · **PR-2** · **Depends on:** `L5-04`, `L3-02`, `L4-04`

## Responsibility

Six tests against a real Radicale 3.7.6 in Docker, gated so they are skipped where Docker is absent
without failing the default `just test`. Every gate compares **parsed-domain `==`** or
**GET-pass-2 vs GET-pass-1**. Also decides and records **Q-3** (emit `VTIMEZONE` vs tolerate) and
records the **iCloud gap** (R69).

> **This ticket is high-risk because its natural assertions are the forbidden ones.** The obvious
> test — "PUT bytes, GET bytes, `assert_eq!`" — is banned by R30 and is permanently red. The obvious
> idempotence proof — "the ETag did not change" — is banned by R31 and is permanently green. See
> §Notes before writing a single assertion.

## RED tests

Module path must be **`live::radicale::…`** exactly (R105 pins the names). Declare
`#[cfg(test)] mod live;` in `caldir-provider-caldav/src/lib.rs` with `pub mod radicale;` inside —
see §Notes on the index's file path.

- **`T-53` `live::radicale::a_u_crawler_task_round_trips_through_radicale_preserving_identity_and_semantics`**
  Push the Stage 2 fixture, pull it back, assert **parsed-domain `==`** on `uid`, `due`, `summary`,
  `description`, `url`, `priority`, `status`, `completed`, and that the pulled item is a `Todo`
  (never an `Event` — R1). A-1 steps 1–4.
- **`T-54` `live::radicale::an_undated_completed_task_survives_a_pull`** — the §9.9 regression lock.
  Fixture: `STATUS:COMPLETED` + `COMPLETED:20200101T000000Z`, **no `DTSTART`, no `DUE`, no
  `CREATED`** (probe fixture `t2`). Push, then `ops::fetch_events` over "today ±365d", then assert
  the task **is in the returned set**. Additionally assert the emitted VTODO REPORT body contains no
  `<C:time-range>` (`prepare_request(...).body()`, no server needed). **This test's whole purpose is
  to fail the moment a `<C:time-range>` is reintroduced on the VTODO query** — Radicale implements
  §9.9 faithfully and will omit this fixture, the remote map loses the entry, and
  `calendar_diff.rs:86` emits an incoming delete against the user's file. Do not add `CREATED` to
  the fixture: `CREATED` rescues the shape (probe `t5`) and would make the test permanently green.
- **`T-55` `live::radicale::get_pass_two_equals_get_pass_one`** — push, `GET` (pass 1), push the
  *same* item again, `GET` (pass 2). Assert **pass 2 == pass 1** as raw bytes. This is the one place
  a byte comparison is legal, because both sides are server-normalized output (R30's second clause).
  Never compare either pass against what was PUT.
- **`T-56` `live::radicale::pushing_a_same_uid_pair_into_one_collection_surfaces_an_error`** —
  R65 / `L5-04`: assert a caldir-level error, and that the pre-existing resource is **unchanged**
  afterwards (probe Q-E.2: Radicale would otherwise silently `204`-overwrite it).
- **`T-57` `live::radicale::the_server_injects_no_non_x_properties_onto_a_task`** — set-difference
  over **property names** inside the `VTODO` component between pushed and fetched. Assert the added
  set is empty and the removed set is empty apart from documented drops. A sibling `VTIMEZONE`
  *component* is expected and must not be counted (R67).
- **`T-58` `live::radicale::renaming_a_local_file_updates_the_same_resource_and_never_a_second_one`** — A-9/R103. **Name corrected (ADJUDICATION):** the original `renaming_a_local_task_file_updates_the_same_resource` is unreachable — a rename reaches a server only via a push, and R70 forbids a task push. It ships on the VEVENT control; the property transfers to tasks **by construction** (`event_url` takes the UID and nothing else), not by measurement.
  Rename the local `.ics`, push, then assert the collection holds **exactly one** resource for that
  UID and its content matches the local item in parsed-domain `==`. Assert the outcome, **not** an
  HTTP status (see `L5-03` §Notes: the reachable 409 trigger is a server-assigned href, not the
  rename itself).

## Acceptance criteria

1. `just test` on a machine **without** Docker passes, running zero live tests and printing a skip
   line per test. `CALDIR_LIVE_RADICALE=1 cargo test -p caldir-provider-caldav -- live::radicale`
   runs all six.
2. The gate is a **runtime** check (`std::env::var("CALDIR_LIVE_RADICALE").as_deref() == Ok("1")`
   plus a `docker --version` probe), not `#[ignore]` — the index's verify command must work as
   written, and `--ignored` would not run under it.
3. The container is torn down **on success, on failure, and on panic**: a `RadicaleContainer` guard
   whose `Drop` runs `docker rm -f <name>`, with a unique name per test
   (`caldir-live-radicale-{pid}-{nanos}`) and a pre-flight `docker rm -f` for stale leftovers. Each
   live test is `#[serial_test::serial(radicale)]` (add `serial_test = "3"` as a dev-dep, as
   `caldir-core` already does) so containers never race for a port.
4. Startup is health-polled (PROPFIND until `2xx`/`401`, ~10s budget) — never a fixed sleep.
5. The setup is reproduced from `radicale-probe.md` §Reproduction: bcrypt htpasswd for
   `testuser:testpass` generated with the image's own venv python, `[rights] type = owner_only`,
   `[storage] filesystem_folder = /data/collections`, published on an ephemeral host port, and
   collections created with `MKCALENDAR`. Base URL is plain `http://127.0.0.1:{port}/testuser/{col}/`
   — `create_caldav_client` allows it (`https_or_http()`, `client.rs:38`).
6. **No test compares raw bytes of a PUT against a GET** (R30) and **no test uses an ETag as proof
   of a no-op push** (R31). A reviewer must be able to grep the module for `etag` and find no
   assertion of that shape.
7. Q-3 is **decided and recorded**: a module-level doc comment in `src/live/radicale.rs` states
   whether caldir emits `VTIMEZONE` for a zoned `DUE`/`DTSTART` or tolerates Radicale adding one,
   with the evidence from `T-53`/`T-55`. Hand that sentence to `L8-06` for `BACKLOG.md`.
8. The **iCloud gap is recorded** (R69): a doc comment stating that these six gates ran against
   Radicale 3.7.6 only, that `caldir-provider-icloud` rides the identical `caldav::ops` code path
   with no mapping layer, and that whether iCloud 409s a same-UID pair, implements §9.9, or injects
   non-`X-` properties is **unmeasured**. Do not claim iCloud task support anywhere.
9. `.github/workflows/ci.yml` is unchanged in behaviour: the TZ matrix keeps running `just test`,
   which skips the live tier. If a live job is added it must be a separate, non-blocking job.

## Notes for the implementer

- **The index says `caldir-provider-caldav/src/caldav/live_tests.rs`, but that yields test paths
  `caldav::live_tests::…`, which contradicts the R105-pinned names `live::radicale::…`.** R105 wins:
  put the module at `src/live/radicale.rs` (`src/live.rs` declaring `pub mod radicale;`, and
  `#[cfg(test)] mod live;` in `src/lib.rs`). Report the deviation; do not rename the tests.
- **Radicale does not echo a PUT** (probe Q-C): properties are sorted alphabetically within each
  component, lines are re-folded at 75 octets, and a `VTIMEZONE` is synthesized for any `TZID`. It
  **is** idempotent — the second round trip is byte-identical, which is exactly what makes `T-55`'s
  pass-2-vs-pass-1 comparison legal and `T-53`'s PUT-vs-GET comparison illegal.
- **Every caldir push mutates the ETag** because `DTSTAMP` is re-stamped on every serialize (R25).
  ETag proves "the remote changed"; it can never prove "nothing changed".
- **Radicale rejects a multi-component `VCALENDAR` with `400`** and logs
  `Multiple component types in object: 'VEVENT', 'VTODO'` (Q-E.4). Never send one — `L5-04`'s guard
  should make that impossible, and `T-56` must not smuggle one in while building its fixture.
- `409 <C:no-uid-conflict/>` is same-UID-at-a-different-href (Q-E.3); same href is a silent `204`
  overwrite (Q-E.2); same UID in a *different* collection is `201` (Q-E.5). Probe shell trap, cost
  two 401s: zsh does not word-split unquoted parameter expansion — pass `-u testuser:testpass`
  literally.
- Trap: `just check` runs clippy with `-D warnings` — an unused import behind the skip gate is a hard
  CI failure. Never run two cargo commands in parallel (`rust-toolchain.toml` pins `1.97.0`).
